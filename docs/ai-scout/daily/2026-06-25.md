## 📝 逐条讲解

### What Makes Interaction Trajectories Effective：用 EGS / TOR 判断 terminal-agent 轨迹是否“可教”
过去做 coding-agent 后训练时，很多团队会自然假设“最强老师模型给出的成功轨迹就是最好的训练数据”，但这篇论文把这个假设拆开验证。作者用 Terminal-Lego 管线把真实问题转成可执行、可验证的 terminal-agent 任务，然后固定学生模型、训练 recipe、任务 substrate 和评测 benchmark，只比较不同老师轨迹的教学效果。结果很反直觉：Claude Opus 4.6 作为单独 solver 分数更强，但用 DeepSeek-V3.2 的轨迹训练出来的学生在 Terminal-Bench 2.0 上泛化更好。论文把原因归结为 Environment-Grounded Supervision，也就是轨迹是否把“观察环境、执行动作、读取反馈、再修正”的过程显式暴露出来，而不是只给学生一串看似聪明但不可复用的动作。它还提出 Targeted Observation Ratio，用来衡量 agent 的观察是否真正指向当前任务所需证据；高 TOR 成功轨迹比随机成功轨迹更适合作为训练数据。最有工程价值的点是，这把轨迹筛选从“最终是否成功”推进到“过程是否能教会学生稳定做事”。对后训练软件工程来说，这类指标可以直接进入 rollout 采集 pipeline：成功轨迹也要按可教性、可验证反馈密度和冗余程度二次筛选。
🔗 链接：https://arxiv.org/abs/2606.03461 ｜ 代码：None

### Agentjacking + agent-jackstop：Sentry/MCP 遥测投毒让 coding agent 执行攻击者命令
Coding agent 接入 Sentry、日志、issue 和监控系统后，调试流程会变得很顺：用户说“帮我修线上错误”，agent 拉取错误详情、读堆栈、改代码、运行命令。Agentjacking 暴露的风险正藏在这条便利链路里：攻击者只要利用公开 Sentry DSN 写入一个伪造错误事件，就可以把恶意“修复步骤”伪装成正常诊断建议。Tenet 的披露称，在受控测试中，Claude Code、Cursor、Codex 等 agent 会把 MCP 返回的错误内容当作可信工具输出，并运行其中的 `npx` 命令；85% 成功率是厂商自报，仍需独立复核，但机制本身非常清楚。这个攻击不要求攻破 Sentry、开发者机器或企业网络，因为链路上的每一步表面上都是“被授权的正常调试”。Tenet 同时开源 agent-jackstop，提供 Cursor 和 Claude Code 的 drop-in hardening 配置，包括默认拒绝网络出口、sandbox、人工批准 gate、敏感文件 denyRead，以及把工具/日志输出视为不可信数据的 skill/rule。它的启发是，prompt 层提醒不够，真正的边界要落在 subprocess、文件系统、网络和工具权限上。对 agent harness 工程来说，任何外部可写数据源进入 agent 上下文前都应带 provenance、trust level 和 action gate，而不是和用户指令混在一起。
🔗 链接：https://tenetsecurity.ai/blog/agentjacking-coding-agents-with-fake-sentry-errors/ ｜ 代码：https://github.com/tenet-security/agent-jackstop

### CodeScaleBench：用 370 个大仓库 / 跨仓库任务量化代码检索 MCP 的真实收益
许多 coding benchmark 的仓库规模较小，agent 失败时很难判断是模型不会改代码，还是它根本没有找到正确上下文。Sourcegraph 的 CodeScaleBench 把问题聚焦到企业真实痛点：大仓库、多仓库、跨服务依赖、组织级代码发现，以及外部代码检索工具到底有没有帮助。它构造了约 370 个覆盖 SDLC 的任务，并做 paired evaluation：同一个 agent 在相同任务上分别使用本地直接读文件 baseline 与 Sourcegraph MCP 检索工具，比较结果、成本、检索质量和轨迹。技术报告显示，MCP 增强后的 Precision@10 从 0.095 提升到 0.313，Recall@10 从 0.120 到 0.272，F1@10 从 0.091 到 0.240；在 canonical paired estimate 中，平均任务成本从 0.7333 美元降到 0.5121 美元。更重要的是，它公开 per-task traces、side-by-side compare pages 和 metrics pipeline，让团队能看到 agent 到底查了哪些文件、走了哪些搜索和编辑步骤。它不是简单证明“MCP 一定更好”，而是在大仓库检索这个具体边界上量化工具收益。对后训练与评测团队来说，CodeScaleBench 提醒我们应把 code retrieval quality 当成一等指标，否则 pass rate 的变化会把模型能力和上下文接口能力混在一起。
🔗 链接：https://sourcegraph.com/blog/codescalebench-testing-coding-agents-on-large-codebases-and-multi-repo-software-engineering-tasks ｜ 代码：https://github.com/sourcegraph/CodeScaleBench

### Ralph Loop 官方插件：把 Claude Code unattended loop 做成 Stop hook + completion promise
社区最近一直在讨论 loop engineering：不是手动一次次 prompt agent，而是让 agent 在测试、lint、git 和任务文件之间循环，直到满足可验证完成条件。Anthropic 管理的 `claude-plugins-official` 中的 Ralph Loop 插件把这个模式做成 Claude Code 内部插件，而不是让用户自己写外部 bash while loop。它的机制很直接：`/ralph-loop` 写入项目级状态文件，Stop hook 拦截 Claude 试图退出的动作，把同一提示重新注入当前 session；agent 每轮能读取自己上轮写到文件和 git 历史里的结果。用户可以设置 `--max-iterations` 防止失控，也可以设置 `--completion-promise` 作为明确停止信号。它的重要性不在于“循环”这个概念新，而在于 unattended agent loop 开始被产品化为可安装、可取消、可限次数、可解释的 runtime 能力。工程上，真正可靠的 loop 还需要测试门、提交粒度、预算、回滚、artifact 审核和危险动作审批；插件本身提供的是最小控制面。对后训练数据采集来说，Ralph-style 轨迹会产生一批很有价值的“失败-验证-重启-改进”循环样本，前提是每轮的验证信号和停止原因被完整记录。
🔗 链接：https://github.com/anthropics/claude-plugins-official/tree/main/plugins/ralph-loop ｜ 代码：https://github.com/anthropics/claude-plugins-official

### SWE-bench-Live 6 月更新：持续刷新、多语言、多 OS 的污染缓解评测继续扩容
SWE-bench Verified 这类冻结 benchmark 的优点是稳定可比，缺点是时间越久越容易被训练语料、调参和采购叙事污染。SWE-bench-Live 的做法是持续从较新的真实 issue 和 PR 中构造任务，并把 live/full split 用于更接近当下的污染缓解评测。6 月更新显示，它继续推进 MultiLang 和 Windows：MultiLang 已覆盖 C/C++、C#、Java、TS/JS、Go、Rust 等语言，GitHub README 记录 743 个多语言 Linux 任务和 61 个 Windows 任务。Leaderboard 还提到新增 MIT-IBM Agent（BOAD）、Brokk Agent、GPT-5.5 和 Deepseek-v4-Pro 结果，并用多次 regression test 过滤无效实例。这个方向的关键不是又多一个榜单，而是 benchmark 也必须像软件一样持续构建、验证和发布。Windows 子集尤其有意义，因为很多 agent harness 默认 Linux 容器，真实企业开发却大量发生在 PowerShell、Windows SDK 和平台特定依赖里。对内部评测工程来说，Live benchmark 的启发是：保留冻结集做趋势比较，同时要有滚动新集和多平台环境来监测真实泛化。
🔗 链接：https://swe-bench-live.github.io/ ｜ 代码：https://github.com/microsoft/SWE-bench-Live

### MCP Server Security Best Practices：把 MCP server 当权限边界而不是开发便利工具
很多团队最初把 MCP server 当作“给 agent 接工具的胶水层”，实现时像内部脚本一样快速暴露 API。Digital Applied 这篇工程指南强调，到了生产环境，MCP server 实际上是一个权限边界：它定义 agent 能看到什么、能调用什么、能以多快速度组合调用，以及外部不可信文本如何进入模型上下文。文章最有价值的提醒是，工具返回的每一个字节都可能由攻击者控制，包括网页、日志、webhook payload、错误消息和搜索结果。它建议围绕最小权限工具注册、schema 暴露收敛、网络出口控制、审计 trail、tool response 标注、季度化 hardening 和异常调用监控来治理 MCP。相比单纯说“防 prompt injection”，这更接近生产 checklist：谁拥有 server、哪个工具有副作用、哪些响应会被 agent 当作指令、哪些动作必须人工批准。它按 Medium 收录，因为不是新论文或 benchmark，但与 Agentjacking、DCIChecker、SafeMCP 等方向形成很强呼应。对 agent 平台团队来说，MCP server 的安全评审应像 API gateway、CI runner 和 secrets manager 一样严肃，而不是作为 demo connector 直接上线。
🔗 链接：https://www.digitalapplied.com/blog/mcp-server-security-best-practices-2026-engineering-guide ｜ 代码：None

### Codex CLI 0.142.1：Windows 系统代理支持进入官方 Codex changelog
Codex CLI 0.142.1 看起来只是一个小版本，但它解决的是企业 agent rollout 中非常实际的网络问题。很多公司 Windows 机器通过 PAC、WPAD、静态代理和 bypass rules 访问外部服务，普通开发工具如果不理解系统代理，就会在认证、下载、API 调用和远程会话上出现隐性失败。OpenAI Developer changelog 6 月 25 日记录了 0.142.1，GitHub release 说明新增 opt-in Windows system proxy support for authentication，并连接到 #26708。这个能力不会直接提高模型写代码分数，却会提高 Codex 在受管企业环境中的可部署性和可诊断性。它也和前几天的 spend controls、Codex logging fixes 呼应：agent runtime 的成熟度越来越体现在代理、日志、存储、预算、认证和可观测这些“平台细节”上。表格按 Medium 收录，是因为它是官方来源且与 agent ops 相关，但不属于新的后训练或评测方法。对内部平台来说，类似 release 应作为兼容性回归项纳入测试矩阵，尤其是 Windows、公司代理、证书链和离线/半离线环境。
🔗 链接：https://developers.openai.com/codex/changelog ｜ 代码：https://github.com/openai/codex/releases

### Codex CLI vs Claude Code 深度命令对比：把 agent 选择落到 sandbox、CI、MCP 与 TUI 差异
很多“Codex vs Claude Code”文章停留在模型偏好或榜单分数，但真实团队选择 agent 工具时，命令面和运行面同样重要。DEV 这篇文章按命令和工作流逐项比较两者，关注点包括交互/非交互模式、sandbox policy、CI 脚本化、MCP 接入、后台 agent 管理、TUI 体验和本地模型灵活性。它的价值在于提醒团队，agent 不是裸模型，而是一组 runtime affordances：能否 dry-run execution policy、能否把另一个 agent 暴露为 MCP server、能否管理后台会话、能否输出结构化结果，都会改变工程落地方式。文章认为 Claude Code 在背景 agent、CI、多 agent pipeline 上更强，而 Codex CLI 在本地模型、sandbox policy、TUI 和 exec policy 方面更细。需要谨慎的是，这类开发者博客可信度低于官方文档和受控 benchmark，且版本变化很快，因此不应当作为最终采购依据。按本日报标准，它作为 Medium/Low 之间的工程参考保留在 Medium，是因为它提供了可执行的评估维度，而不是只给主观结论。对我们关注的 harness 工程来说，最可借鉴的是把工具选择拆成“任务类型 + 权限模型 + 验证方式 + 成本/延迟 + 团队控制面”，再做内部小型 benchmark。
🔗 链接：https://dev.to/qainsights/codex-cli-vs-claude-code-a-deep-dive-command-comparison-1i12 ｜ 代码：None

### OpenAI + Broadcom Jalapeño：面向 LLM inference 的首代 OpenAI 自研加速器
OpenAI 6 月 24 日与 Broadcom 发布 Jalapeño，这是 OpenAI 首代面向 LLM inference 的自研 Intelligence Processor。它不属于 coding agent 或后训练数据工程主题，因此按 Low 收录，但它是近月官方源新增内容，且会影响 agent 产品的长期成本与延迟边界。OpenAI 称该芯片围绕 LLM inference 设计，目标是减少数据移动、平衡 compute/memory/networking，并让实际利用率更接近理论峰值。发布中特别强调，Jalapeño 从早期设计到 tape-out 只用了九个月，其中包括 OpenAI 模型辅助部分设计和优化流程。当前还没有完整性能报告，官方只说 early testing 的 performance per watt 会显著优于当前 state-of-the-art，详细技术报告将在未来几个月发布。对 agent 工程的间接意义是，长程 Codex、ChatGPT、API 和 future agentic products 的成本曲线最终不只由模型算法决定，也由推理芯片、网络和机架级系统共同决定。短期内它不是可复现技术条目，但作为 OpenAI 官方 infrastructure 信号，值得在官方源专栏中跟踪。

### 🔥 大佬观点

**Boris Cherny / Claude Code 生态：工程师的下一层抽象是写 loops。**  
围绕 Ralph Loop、WorkOS/Meta @Scale 访谈和多篇社区解读，Boris 的核心观点被反复引用：开发者不再只是直接 prompt agent，而是写会读取 GitHub、Slack、Twitter、测试和文件系统的循环，让循环决定下一步。这个观点值得注意，因为它来自 Claude Code 的核心构建者，并且正在被官方插件、社区脚本和团队实践同时产品化。🔗 https://explainx.ai/blog/loop-engineering-coding-agents-claude-code-guide-2026

**Tenet Security：agent 真正的攻击面是“可信工具输出 + 本地行动权限”的组合。**  
Agentjacking 的讨论之所以热，是因为它不是单个 vendor bug，而是 coding agent 共同的系统模式：外部可写数据通过 MCP 进入上下文，随后 agent 用开发者权限执行命令。它提醒安全团队，评估 Sentry、GitHub、日志或搜索 connector 时不能只看单个工具是否安全，还要看 agent 组合权限、网络出口、文件读取和人工批准路径。🔗 https://tenetsecurity.ai/blog/agentjacking-coding-agents-with-fake-sentry-errors/

**Sourcegraph / CodeScaleBench：更好的代码检索有时比更贵模型更值钱。**  
Sourcegraph 用 CodeScaleBench 衍生实验强调，在大仓库发现型任务上，较便宜模型加高质量代码检索 MCP 可以击败更贵模型的本地盲读配置。这个观点值得注意，因为它把“买更强模型”拉回到“改上下文接口、符号检索、跨仓库导航和 trace 可观测性”这些工程杠杆上。🔗 https://sourcegraph.com/blog/sourcegraph-mcp-and-a-cheaper-model-beat-a-mythos-class-model-alone

### ⭐ 超火仓库/项目

**anthropics/claude-plugins-official / Ralph Loop：官方插件把 unattended coding loop 标准化。**  
该仓库是 Anthropic 管理的 Claude Code 插件目录，搜索结果显示已有数万 star，Ralph Loop 通过 Stop hook、completion promise 和 max-iterations 把“反复运行 agent 直到完成”做成可安装能力。它火在解决一个真实痛点：长程 coding agent 不能只靠一次 prompt，需要可控循环、明确停止条件和文件/git 作为状态载体。🔗 https://github.com/anthropics/claude-plugins-official/tree/main/plugins/ralph-loop

**tenet-security/agent-jackstop：Agentjacking 披露后的第一批 drop-in hardening 配置。**  
项目本身很新、star 不高，但热点来自安全事件本身：它给 Cursor 和 Claude Code 提供默认拒绝网络出口、sandbox、permission rules 和“untrusted tool output”skill/rule。它解决的是生产化 agent 最急迫的问题之一：当 prompt 防线失效时，能不能在命令执行、网络访问和敏感文件读取处把攻击挡住。🔗 https://github.com/tenet-security/agent-jackstop

**sourcegraph/CodeScaleBench：大仓库 / 多仓库 agent eval 开始有可审计轨迹资产。**  
CodeScaleBench 不只是一个分数表，它公开任务、run snapshots、side-by-side trace compare 和 retrieval metrics，便于团队复盘 agent 为什么找对或找错上下文。它火在填补 SWE-bench 式小仓库 bugfix 与企业真实代码发现之间的空白，并把 MCP 检索工具的 ROI 变成可量化问题。🔗 https://github.com/sourcegraph/CodeScaleBench
