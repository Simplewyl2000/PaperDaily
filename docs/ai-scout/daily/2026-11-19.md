## 二、逐条中文讲解

### 1. Context Has a Price: Adding and Removing Context for LLM Coding Agents under Prefix Caching

编码代理每次都把对话历史再发给模型。常见的省法有两种：把相关代码检索进来，少让模型自己翻仓库；或者删掉旧的工具输出，让后面的提示变短。前缀缓存已经很常见，缓存过的输入往往只按未缓存价格的一折计。少发出去的字，不一定还是少花的钱。

这项测量把未缓存输入、缓存输入和输出分开计，用开源权重模型在 SWE-bench Verified、SWE-bench 和 Loc-Bench 上跑了两万多次。在主要的证据包实验里，检索进来的代码让读文件和搜索少了 18% 到 34%，按一折缓存计价时总费用却高了 33% 到 42%，解决率没有测出提高。删掉旧观察，在没有缓存折扣时能省 19% 到 36%；同样的删法，在一折缓存下费用上升 38% 到 116%。提示更短以后，代理也可能多走几步。同时跑的实验还会共用缓存前缀，把费用对比带偏。

按缓存价计，少给上下文可以更贵；费用要连同代理随后多走的步一起算。

**链接：** [原文](https://arxiv.org/abs/2611.22238)

### 2. Higher-Scoring Coding Models Did Not Get More Work Done

新模型发布时，编码基准上的分数差会被当成更能干活的证据。缺少的是一次人和项目都不变、只换模型的比较，再看真实仓库里的拉取请求有没有更常被合并。2026 年 6 月 12 日，一项出口管制让 Claude Fable 5 停用 19 天，原来的用户大多改用 Opus 4.8。论文写，后者在 SWE-Bench Pro 上低 11 分。

作者把这次停用当成自然实验。处理组是 297 名原先使用 Fable 5 的人，对照是 8,908 名一直使用 Opus 4.8 的开发者，人和日期都放进固定效应。七天内合并率只高 1.4 个百分点，区间是 −1.4 到 +4.3，没有显著。停用前后的五次模型升级里，1,208 名开发者、15,442 个拉取请求的加权平均是 −0.9 个百分点，区间 −1.9 到 +0.2；五次估计都是负的，区间都含 0。每周合并条数是 +2.4%，区间 −4.9% 到 +10.2%。合并率很粗，区间也宽，很小的真实差异没有被排除。

这次没有测出更高的基准分带来更高的合并率。

**链接：** [原文](https://arxiv.org/abs/2611.23216)

### 3. Does Your Agent Need to Know Its Budget? A Placebo-Controlled Experiment on LLM Coding Agents

部署编码代理时，组织会设 token 上限，也会把还剩多少写进提示，希望模型自己省着花。上限会不会降低做成任务的比例，以及“告诉模型还有多少预算”有没有额外作用，之前没有分开测。不放进一句无关的话，就分不清效果来自预算信息，还是来自多写了一句提示。

作者用冻结并打了时间戳的方案，在两个可执行的程序修复基准上做安慰剂对照：是否强制执行预算，以及是否把预算告诉模型。5,835 次运行、两个开源权重模型、三档上限。执行校准过的上限后，任务解决率降了 20.0 个百分点，每个做成的任务所用 token 大约降为原来的十二分之一。把正在执行的预算告诉模型并没有帮助。相对那句无关的话，中等上限的风险差是 −2.8 个百分点，区间 −6.2 到 +0.7；最紧的一档是 −4.2，区间 −8.1 到 −0.2，没有做多重校正，只是名义上显著。各种措辞和每回合反馈都远低于他们事先关心的 10 个百分点。相对沉默执行，一句无关的句子反而把解决率抬高 7.2 个百分点，区间 +4.0 到 +10.5。

预算要靠强制执行来省 token；把预算告诉模型，这次没有超过一句无关的话。

**链接：** [原文](https://arxiv.org/abs/2611.21614)

### 4. Research acceleration: The jagged frontier

实验室想知道编码代理有没有在加快自己的研究。只看花了多少钱，分不清是模型更贵、用得更勤，还是真的做成了更长的任务。任务种类也不一样：看着一次训练，和写一套推理服务，不是同一件事。

OpenAI 用内部记录更新了这项测量。从 3 月到 10 月，估计需要人做两到四小时的任务，无人介入就做成的比例从 23% 到 46%；四到八小时从 13% 到 35%。作者注明，代理变强以后，放进同一时长档的任务也可能变了，所以涨幅不全是能力。按任务种类，8 月 1 日到 10 月 18 日，看着训练运行找问题大约 79%，启动训练大约 35%，为推理和服务栈写代码大约 25%，搭建评测、强化学习和代理环境大约 29%。被问到的后训练和安全监测研究者说，GPT-6 Astra 和 6.2 上他们点名的想法是人提出的，模型负责实现；预训练在 6.2 上有人是和 Codex 一起把想法做出来的。

研究代理的完成率按任务种类分开，写评测环境仍远低于看着训练。

**链接：** [原文](https://openai.com/index/research-acceleration-jagged-frontier)

### 5. Revision-Consistent Code Context for Agents That Edit Their Environment

编码代理一边改仓库，一边问符号在哪、谁调用了它。源码、符号和调用图常常分开放，刷新也不同步。一次查询可以成功返回，里面的事实却从来没有同时存在于同一个修订。代理接着改，就是对着一个没出现过的仓库状态动手。

这篇工作要求：在一次对代理可见的发布点之前，服务只能等待、报告不可用，或给出完整的旧修订；过了这个点，就给出完整的新修订。同一次响应里的每种视图共用同一个版本。Codetrip 用这个约定把源码、符号和图接在一起。在冻住的 Gin 1.12.0 上，五种编辑、150 次更新里，直接拼活源码出现 2 次不安全响应，完整修订发布是 0 次。把真实的 MCP 进程在五个可恢复边界杀掉，Gin 和 Cobra 上 300 次可评恢复都回到与干净全量重建等价的新上下文，从重启到能查询的中位时间是 77 到 131 毫秒。另一次重命名探针里，混合上下文在 Codetrip 的 30 次里是 0，在 CodeGraph 和 codebase-memory-mcp 收敛之前是 30/30。论文页面链到的仓库本次查询是 0 星，最近推送停在 8 月 31 日。

一次查询里的源码、符号和图，必须来自同一次仓库修订。

**链接：** [原文](https://arxiv.org/abs/2611.21616) · [代码](https://github.com/mengshi02/codetrip)

### 6. EmbedGym: Letting Coding Agents Develop and Debug Embedded Firmware Without Physical Hardware

编码代理能在普通软件上形成闭环，是因为写完可以跑测试。嵌入式固件不是这样：程序编译通过，仍可能在引脚极性、总线、时序或联网上失败，坐在文本终端前的代理看不见板子。现有做法要么不跑硬件，要么用只有通用引脚、每次要等数秒的模拟器，要么在一块不会变化的真板上测。

EmbedGym 用指令级单片机模拟器执行那份本来要烧进板子的二进制，接上 41 个外设模型、模拟电路，以及虚拟的 Wi-Fi 和低功耗蓝牙。代理可以改传感器读数、按按钮、查看硬件状态。上面的基准有 598 道题、6 组单片机与框架，用隐藏的带时间测试向量评分；外设和题目由一个五阶段流程从数据手册和驱动库生成。八个模型、超过 1.4 万条轨迹里，编译成功率 99.7%，编过的固件仍有 19.9% 在运行时失败，单个目标上最高 73%。让代理在这个环境里做交互测试后，各模型通过率提高 4.9% 到 14.7%，单个目标上最高 31%。带上这个环境的轻量模型，能以大约 30 到 70 倍更低的成本，赶上不带它的前沿模型。论文页面没有给出代码仓库。

固件编译通过不够；代理要能改传感器、看硬件状态，运行时的失败才看得见。

**链接：** [原文](https://arxiv.org/abs/2611.21845)

### 7. The Resolution Hypothesis: Agent Evolution's Key Is Identifying Improvements

让代理进化提示、技能或记忆时，常见循环是一个提议者写出候选，选择器留下分数更高的那个。方法之间经常互相换胜负，有些任务上循环根本长不起来。这很容易被看成“没有人提出更好的改动”。

作者把它收成分辨假说：候选里已经有有帮助的改动，但有噪声的分数分不出它和有害的改动，选错会一轮轮累积。七种进化方法、六个模型、超过一千万次模型调用里，选择器和随机挑选一样，分不清有帮助和有害的候选。比方法时，常见的几个百分点差距，小于同一种方法独立跑两次的差别，所以发表出来的名次经常落在运气里。这是他们这套打分和对“有帮助”的定义下的结果。

自改进停住，常常是因为评测认不出改进。

**链接：** [原文](https://arxiv.org/abs/2611.23068)

### Trending Open-source Projects

#### 1. rust-anything

把一个还能跑的程序改写成 Rust，通常要等一大块重写完，才知道行为有没有变。编码代理可以写 Rust，但没有一份“原程序在这些输入上返回什么”的记录时，它只能靠读代码猜。热路径如果一次只搬一个调用，跨语言的调用开销还会把加速吃掉。

rust-anything 先跑原程序，记下边界输入、语义陷阱，以及可选的原测试套件里每次调用的返回或异常，再生成保持原接口的 Rust 外壳。对照步骤把每条记录拿到 Rust 上重放，过不了门就不能当完成。热循环要整批留在 Rust 里。项目文档里，x18n 在 5 万个键上逐字搜索，TypeScript 每次查询约 10 毫秒；按次调用的移植只有原来的 0.2 到 0.4 倍，带索引的批处理是 18 到 22 倍。Go 和 Java 的字符串批处理大约是 4 倍和 3 倍。首页写着回放 38,251 条记录、0 次不一致。通过只说明记录过的输入对得上。没录到的输入、正则在非英语文本上的差别，以及返回值以外的时序和副作用，都不在这份通过里。仓库 11 月 16 日创建。本次接口查询 3,438 星、274 个分叉，11 月 18 日仍在推送。我抓到的当日趋势页前排没有它。

它把改写是否还做同一件事收成可以重放的记录。加速取决于热循环有没有整批留下，按次搬运可以更慢。

**链接：** [GitHub](https://github.com/erkamyaman/rust-anything)

#### 2. PEAR

让开源权重模型操作真机器人，以前主要靠示范，或者靠闭源前沿模型。示范覆盖不到的新任务会让视觉-动作模型掉下去。如果模型像操作电脑那样自己看、自己想、直接给出下一步末端位姿，训练就需要能大规模重置的环境。

PEAR 是 MIT HAN Lab 的后训练引擎，在模拟器里用强化学习训练这种用法，不用示范，也不在模型外面套一层专门的机器人脚手架。模型观察环境，写出思路，再给出下一步末端位姿。论文报告，在 LIBERO 和 RoboDojo 的模拟任务上训练之后，一个 27B 开源权重模型在他们的真双臂试验里做成 60%，训练前是 0。LIBERO 成功率从 1.6% 到 74.4%。换到熟悉场景里的新任务，对照的示范微调模型是 0.75%，这个模型是 57.4%。九个推理、编码和视觉基准上没有测出通用能力下降。仓库 11 月 13 日创建。本次接口查询 677 星、42 个分叉，11 月 18 日仍在推送；它不在我抓到的趋势页前排。

模拟里的强化学习，可以让不靠示范训练的开源模型在真机上做成任务；60% 是他们这组试验。

**链接：** [GitHub](https://github.com/mit-han-lab/pear) · [论文](https://arxiv.org/abs/2611.18562)
