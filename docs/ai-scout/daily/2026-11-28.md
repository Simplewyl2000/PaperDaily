## 二、逐条中文讲解

### 1. Migrating our Messages API to Rust

编码代理写迁移已经很快，难的是仍在线上、还在改的服务：用户依赖测试没写到的边角行为，什么叫对也会跟着新模型和新功能一起变。Messages API 是客户以及 Claude Code、Cowork 到达模型的主路径，从 2024 年初到 2026 年秋，请求大约涨了 1,800 倍。先把解析输出改成 Rust，CPU 大约少 8% 到 10%，每个 token 却要在 Python 和 Rust 之间来回三次。Claude 大约一周写出核心路径的第一版，到 5 月它已经写下 Anthropic 合入代码的 80% 以上；Python 版还在改，同一请求的回复也不确定，他们又不能读客户请求，两版差在哪里不能靠对原文。

已有大约 700 个集成测试，和 Python 绑在一起，搬过去之后审计发现超过 100 处断言被放宽；4 月时 Rust 大约通过其中 98%，生产流量上输入能对上的只有大约四分之一。模型只跑一次，同一段输出重放给两版，按步骤记下接受还是拒绝、提示的哪一块、第一处不同的字节和两边长度，记录里没有请求原文；同一种差异留下同一枚指纹，脚本每 10 到 30 分钟分组，只在新指纹出现时派一个工人。工人自己写请求去复现，本地检查不调用模型、不到一秒，对上之后要补一条旧代码会失败的测试；人在补丁进入外环时看，因为检查只要求两边一致。网页搜索的工具描述没接上时，把文字抄进文件就能通过，工程师拒绝了，上线前仍要去调那个服务。外环用影子流量看这条指纹还在不在，评审里的纠正写成后面每个代理都会读的规则；公开流量在 9 月切到 Rust，文中总结为每请求 CPU 大约少 70%（图里的 CPU 来自一个区域），Claude Code 请求的中位首 token 时间大约少 20%，服务没有下线，功能开发也没有停。

活系统迁移能不能做完，取决于验证信号能不能指出差异在哪，并且挡得住只求两边一致的修法。
