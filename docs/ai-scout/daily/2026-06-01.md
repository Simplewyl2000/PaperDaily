## 📝 逐条讲解

### ProgramBench：语言模型能从零重建完整程序吗？
Meta 提出的新基准，把"写软件"从修单个 bug 升级到"重建整套程序"：只给智能体一个程序的二进制和文档，要求它自行做架构决策并实现一个行为对齐参考可执行文件的代码库，测试用例由 agent 驱动的 fuzzing 自动生成。200 个任务从小型 CLI 工具到 FFmpeg、SQLite、PHP 解释器。结果非常打脸——9 个模型没有一个能完整通过任意一个任务，最好的 Claude Opus 4.7 也只在 3% 任务上通过 95%+ 测试，且模型偏好单文件巨石实现。这是衡量长周期自主编码能力上限的好标尺。
🔗 链接：https://arxiv.org/abs/2605.03546 ｜ 代码：https://github.com/facebookresearch/programbench

### Agentic Harness Engineering (AHE)：可观测性驱动的 harness 自动进化
Harness（围绕基座模型的系统提示、工具、中间件、记忆等"脚手架"）正成为 coding agent 性能的决定性因素。AHE 把 harness 拆成七类可独立编辑的文件，并用三个"可观测性支柱"驱动自动进化：组件可观测（每个组件单独成文件、可回滚）、经验可观测（把数百万 token 轨迹蒸馏成分层可下钻的证据库）、决策可观测（每次修改都附带可证伪的预测，下一轮用真实结果验证，无效就回滚）。10 轮迭代把 Terminal-Bench 2 的 pass@1 从 69.7% 提到 77%，超过人工设计的 Codex-CLI，且冻结后的 harness 还能跨模型族迁移涨点。把"调 harness"从手工活变成可自动收敛的工程闭环。
🔗 链接：https://arxiv.org/abs/2604.25850 ｜ 代码：None

### TEBench：项目级测试演化基准
现有测试相关基准大多只看单点输入，TEBench 第一个在"项目级"评估测试演化：给定仓库和一个改代码的 commit，要求系统自主找出需要修改的测试、判断哪里需要新增测试并产出测试补丁。它从 Defects4J 生态筛出 314 个任务，标注三类演化——Test-Breaking（失败）、Test-Stale（仍过但已失去校验意义）、Test-Missing（需新增）。在 Claude Code、Codex CLI、OpenCode 三套框架上，识别 F1 都卡在 45.7%~49.4% 的天花板，其中 Stale 最难（~36%），因为现有方法依赖"执行失败"信号、缺乏主动语义推理。揭示了当前编码 agent "执行-失败-修复"反应式循环的结构性短板。
🔗 链接：https://arxiv.org/abs/2605.06125 ｜ 代码：https://github.com/iSEngLab/TEBench

### Claude Opus 4.8 与 Dynamic Workflows
Anthropic 5 月 28 日发布 Opus 4.8，价格不变但 agentic 编码、推理、computer-use 全面提升（SWE-bench Verified 88.6%、SWE-bench Pro 69.2%）。对 Coding Agent 最重要的是同步推出的 Dynamic Workflows：Claude Code 可以自己规划任务、在单次会话里编排数百个并行子代理，并在汇报前自我验证产出——官方称已能以现有测试套件为标准，端到端完成跨数十万行代码的代码库级迁移。同时模型"诚实度"提升，放任自己写的代码缺陷不报的概率约降到前代的四分之一。这是 harness/编排层能力进入产品的标志性一步。
🔗 链接：https://www.anthropic.com/news/claude-opus-4-8 ｜ 代码：None

### MicroCoder-GRPO：打破代码模型 RL 训练瓶颈
针对现代代码模型"输出更长、能力增长更快"导致传统 RL 方法失效的问题，提出改进版 GRPO 三招：条件截断掩码（提升长输出潜力又保持稳定）、多样性决定的温度选择、去掉 KL loss 并用高裁剪率以鼓励解的多样性。在 LiveCodeBench v6 上相对强基线提升最多 17.6%，长上下文下更明显。还开源了更难的 MicroCoder-Dataset（300 步内涨幅是主流数据集 3 倍）和评测更准、更快的 MicroCoder-Evaluator，并总结了 34 条训练经验。对做代码 LLM 后训练的团队是很实用的工程参考。
🔗 链接：https://arxiv.org/pdf/2603.07777 ｜ 代码：None

### 用离线 RL 高效后训练代码模型
在线 RL 做代码生成要不断推理+验证，既慢又贵。本文系统研究"完全离线"设定：直接在预先收集好的代码数据上做策略梯度，省去在线采样。实验显示离线 RL 能稳定提升 pass@1 和 pass@10，尤其对小模型和难题收益最大，且在严格算力约束和高度不平衡数据下依然有效；其中 RLOO 配 GRPO 式优势估计效果最稳，凸显方差缩减的重要性。给算力有限但想做代码 RL 的团队一条低成本路径。
🔗 链接：https://arxiv.org/abs/2605.28409 ｜ 代码：None

### RE-PO：用 EM 可靠性加权应对噪声偏好
偏好对齐数据里的标注常常有噪声、不一致，而多数方法默认所有偏好对同等可靠。RE-PO（ICLR 2026）引入 EM 式的可靠性感知加权：E 步估计每个标签为真的后验置信度，M 步用这些置信度作为权重更新策略参数和标注者可靠性，整体训练流程仍贴近 DPO。在 Mistral-7B / Llama-3-8B 上对 DPO、IPO、SimPO、CPO 等家族普遍提升 AlpacaEval 2 的 LC/WR，且估计出的可靠性能跟踪人造噪声趋势。是一个即插即用、增强偏好优化鲁棒性的通用框架。
🔗 链接：https://repo-alignment.github.io/ ｜ 代码：https://repo-alignment.github.io/

### CDPO：因果直接偏好优化
人类偏好数据常受"用户目标、专业度、文化、任务"等可观测混杂因素影响，导致模型学到的是被偏置的反馈而非真实意图。CDPO（EACL 2026 Findings）把因果推断引入 DPO，用后门调整（backdoor adjustment）校正这些可观测混杂，从而比标准 DPO 更鲁棒。相比只调 β 的 β-DPO，它从因果结构层面解释并缓解偏置来源。对关心对齐数据偏差的团队是个新视角。
🔗 链接：https://aclanthology.org/2026.findings-eacl.58.pdf ｜ 代码：None

### OAPL：拥抱 off-policy 的策略优化
分布式训练里训练策略与推理策略天然存在滞后，数据本就 off-policy；以往做法是用重要性采样或改推理引擎把数据"伪装"成 on-policy。OAPL 反其道而行，直接拥抱 off-policy：提出带滞后推理策略的最优优势策略优化，无需改造推理引擎。它在竞赛数学上超过带重要性采样的 GRPO，在 LiveCodeBench 上用少 3 倍的生成量就能匹配 DeepCoder，并能容忍 400+ 梯度步的滞后（比以往方法 off-policy 程度高 100 倍），还改善了 Pass@k 的测试时扩展。对大规模分布式 RL 训练的吞吐很有价值。
🔗 链接：https://arxiv.org/abs/2602.19362 ｜ 代码：None

### OpenAI 模型证伪 Erdős 单位距离猜想
5 月 20 日，OpenAI 称其一个**通用**推理模型（非专门的定理证明系统）自主给出了离散几何中 1946 年 Erdős 单位距离猜想的反例——构造出一族无穷例子，比长期被认为最优的"方格"构造多出多项式量级的单位距离对，关键工具竟来自代数数论。该证明由 9 位外部数学家验证并写了配套论文。OpenAI 称这是"首次由 AI 自主解决一个学科核心的著名开放问题"。对评估推理模型能否做真正原创研究是标志性事件。
🔗 链接：https://openai.com/index/model-disproves-discrete-geometry-conjecture/ ｜ 代码：None

Google 在 I/O 2026（5 月 19 日）发布 Gemini 3.5 系列的首个模型 3.5 Flash，定位高吞吐、主打 agentic 编码与软件任务，官方称在部分挑战性基准上已超过上一代旗舰 3.1 Pro，并强调 Terminal-Bench 等编码相关分数。它同时接入 Antigravity agent 工作区、Gemini API（含 Managed Agents）与企业 agent 栈，体现 Google 把"模型+agent 运行时+IDE+部署"打包成一套的策略。对关注大厂编码 agent 生态的团队值得留意。
