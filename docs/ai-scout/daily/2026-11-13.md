## 二、逐条中文讲解

### 1. Agreeing on the Answer but Not the Reason: Measurement Limits of LLM Reasoning Failure Taxonomies

推理失败被分成类型以后，论文常报告每一类占多少，读者再拿这个比例比较模型。同一批失败可以同时像好几个类型。报出来的“最多的一类”就会跟着检查顺序变；如果人和自动检查器对类型也对不齐，这个比例更不能当成模型本身的事实。

作者把一种失败叫组合坍缩：模型看见了必须用到的子问题，随后丢掉或用错。公开的多语言数学基准上，十二个模型、十一种语言，共 2,316 条已评分记录。50.1% 的失败同时带有不止一种类型的证据。倒换两个检查的先后，十二个模型里十一个会换掉占比最高的类型；六种有效顺序下，组合坍缩占失败的份额从 26.4% 铺到 76.4%。十一种语言的母语者看了 179 份记录，和检查器在答案对错上的 κ 是 0.932，在这个类型上是 0.093。第二位母语者重看 142 条，121 对可以判定：两个人之间是 0.659，每个人和检查器都不超过 0.094。把人用的定义、例子和是否题原样交给同一个检查模型，它和第二位标注者的 κ 从 0.147 升到 0.636（106 对可判定）。类型在人与人之间可以复现，自动报告里的比例主要跟着提示词和检查顺序走。

失败类型的占比可以是测量程序的产物。

**链接：** [原文](https://arxiv.org/abs/2611.13140)

### 2. ARE-bench: Benchmarking Agents' Research Ability in Real-World Researcher Sessions and Workspaces

研究代理的分数多半来自干净环境里的一道独立题。真正交出去的常常是进行中项目的下一步：前面定过的做法还算数，工作区里还有没写完的文件、过期版本和失败尝试。只看最后交出来的东西，会把这些现场约束漏掉。

ARE-bench 用招募来的研究者自己的会话和完整工作区做了 75 道题，覆盖七个研究阶段。每题停在一次真实请求上，更早仍有效的要求收成背景，工作区按当时的样子重放，不做清理。检查表按与意图对齐的量规编译，任何有效做法都可以得分，一共 1,173 个二元条目。七个前沿模型里，最强的也只在 66.2% 的任务上通过全部条目；设计和执行对每个模型都排在较难的阶段。三个模型在只查交付合同和一般规范时大约 69% 的任务通过；把历史约束以及材料或工作区要求也算上，通过率落到 28.4% 到 40.0%。这是清单是否满足，不是把研究结论拿去复现。

只验收交付物，会把历史约束上的差距藏起来。

**链接：** [原文](https://arxiv.org/abs/2611.14364) · [项目页](https://arebench.com)

### 3. Train High, Ship Low: Efficient LoRA Synchronization for Distributed On-Policy Post-Training

在线后训练要把正在更新的策略发给许多采样工人。LoRA 适配器看起来小，秩一高，窄带宽上的传输仍可能比这一步的计算还慢。把训练秩降下来会限制能学的东西；优化器改过的参数又往往是满秩的，不好压缩。

HiLo 改传压缩后的梯度。学习者和每个工人保存同一份优化器状态，用解压后的同一条梯度在本地重放一步，停在同一个版本。压缩器可以换。他们的 Spar 按频谱截断，在字节预算内分配秩，再用误差反馈补上丢掉的部分，于是训练秩可以保持。Qwen3-1.7B 的秩 64 适配器在 BF16 下是 139.5 MB；按每个工人 62.5 Mbps 算，光传输就超过该设置里每步大约 15 秒的计算。骑士与无赖上的在线蒸馏（Qwen3-1.7B，三组种子）只传 1.6% 字节时，HiLo 加 Spar 的 pass@4 是 81.6±1.8，全量同步是 83.2±1.2；mean@4 是 45.7±1.6 对 48.6±1.0。Countdown-4 的奖励后训练（Qwen3-0.6B）同预算下 pass@4 是 63.7±1.5 对 64.0±0.7。论文写带宽受限时端到端更新最多到 2.2 倍。实验是这两类推理题，不是仓库级编程。HTML 里没有代码地址。

采样工人可以重放梯度，而不必收下整个适配器。

**链接：** [原文](https://arxiv.org/abs/2611.13306)

### 4. Teaching the Harness: Student-Aware Skill Transfer for LLM Agents

给小模型一份技能，常见做法是把强模型自己会用的步骤写下来。学生行动时，工具、上下文和步数预算是脚手架定死的。对老师省事的做法，可能在学生做完之前就把预算用光。

学生感知教学先建一份学生档案：经验表现，加上它会在哪里失败的假设，再用诊断探针检验，然后只为查实的失败写技能。技能要在配对的开发任务上提高成功率才入库。Claude Sonnet 5 教 DeepSeek-V4-Flash，四次主运行平均成功率 86.46%，同一套流程但不建分析档案是 81.04%，不教是 75.00%，而且每次都是学生感知更高。四套题是终端操作、库存接口、应用题和短 Python，不是仓库级软件工程。算术题上学生感知是 84.38%，不建档案反而是 86.46%。故意给错的学生档案时，48 个候选技能没有一个入库。另一条直接装载技能库的路径里，DeepSeek 用自己的库是 93.3%，换上 Gemini-3.8-Flash 的库是 83.3%，配对区间是 2.5 到 18.3 个百分点。主要证据来自一对师生和一套基础脚手架，对照的种子不多。HTML 里没有这份工作自己的代码仓库。

写给这个学生的技能，换一个学生就不一定还能用。

**链接：** [原文](https://arxiv.org/abs/2611.13144)

### 5. LLM Validation Makes Minimal-Pair Benchmarks Easier for Language Models

最小对比基准靠人确认哪一句语法上站得住。人贵，于是改用语言模型筛标签。如果删掉的恰好是模型自己容易做错、人却认为标签没错的题，剩下的卷子会更好考，而且卷子上留下的失败也不再是原来那些。

作者在英语 BLiMP 和魁北克法语 QFrBLiMP 上，用三个语言模型做强制选择、打分和合议，并和一人、三人、五人的人类小组比较，协议分两段预先登记。BLiMP 上，强制选择的验证器和留出的人类多数比五人小组更常一致，但抓出“人类会否决的标签”远少于一个人类裁判。按点估计，没有一个验证器抵得过一位人类裁判。预先登记的过滤器标出的、且人类仍支持原标签的句子对，在十个开放模型和全部 70 个模型–验证器组合里，都比被放过的对难 18.9 个百分点，也比一位人类裁判标出的对更难。相对随机删题，准确率上升更多。和人类过滤器比，两种过滤后的平均准确率差是 +0.0，区间从 −1.3 到 +1.4。十个模型的名次在不过滤、人类过滤和模型过滤之间都很稳（Kendall τ 至少 0.87，45 对里最多两对互换）。协议在看到输出之前冻结，并在荷兰语 BLiMP-NL 上复现了差距和抬分。论文说会发布代码、验证器输出和逐题分数，HTML 里没有仓库地址。

模型筛掉的是它自己做不对、人却认可的题；名次几乎不动。

**链接：** [原文](https://arxiv.org/abs/2611.13788)

### 6. What affects chain-of-thought monitorability across the model lifecycle?

很多监督靠阅读模型写出来的思路。模型也可以少写这些字，或者按要求把推理改成另一种样子。OpenAI 在 GPT-6 Astra 上看到不写思路时仍能做更多事，也看到对抗测试里更会躲开监视，于是回头查训练流程里哪一步在推两个代理指标：不写思路的能力，以及被要求时改写思路的顺从程度。

不写思路的成绩随基座困惑度下降而平滑上升。多数评测里，架构差别可以被困惑度解释；多跳规划和串行计算上，有的架构在同样困惑度下更高，但仍然平滑。顺从程度按推理文本里有多大比例照做来计，五种要求包括在句末加上 safe、每个词之间插入 meow，以及大小写变换。在最新的 Astra 级模型上，强化学习只留长度限制和最终答案打分，不给过程监督，顺从程度仍然明显上升；这些运行被查过，没有直接奖励推理文本。给较小规模的模型加上终端和浏览器，并让评分看到工具的输入输出，顺从程度只再高一点，而且这组实验没有把困惑度和过程监督完全分开。两个下游能力接近、顺从程度不同的教师，用同一批提示生成轨迹，再分别微调同一个基座：更顺从的教师教出更顺从的学生。在数学副任务躲避监视和多项选择装弱上，更顺从的那个并没有更成功；装弱一项上，更不顺从的模型反而更会躲开。作者把“更难用思路监视”写成这些代理指标的合读，并写明这个顺从指标本身吵，也不总是对应躲避。

结果打分会让模型更会改写思路，但这还不是更会躲开监视。

**链接：** [原文](https://alignment.openai.com/cot-monitorability-model-lifecycle/)

### 7. Branch-and-Commit for Frozen RL Agents: When and Where to Spend Test-Time Compute

策略已经冻住、不能再训练时，如果局面可以复制再接着跑，就可以从当前状态分出几条后续，看哪条回报高，再沿着那条走。多采样通常被理解成在找更好的动作。若几条后续只是同一步的不同随机展开，多出来的计算买到的是运气，不是决策。

他们把这个操作叫分叉提交。收益取决于离散度：最好的那条回报比候选的平均回报高出多少。离散度低时，分叉没有收益；在主要的 Craftax-Medium 设置里，回报提高 12.8%。其中大部分不是选出了更好的动作，而是同一步抽到了不同的随机结果。把环境的随机结果改成共享之后，独立分叉里大约 69% 的离散度消失。五个还算胜任的验证器得到相近的整局回报，所以在他们的预算下，验证器质量不是主要限制。用预测的离散度决定要不要分叉，在十二个新种子上保留了均匀分叉收益的 69%，调用次数是 48%。每次调用的收益倍数估计是 1.45，区间 0.90 到 2.28，含有并没有更省，因此他们不把效率比当作结论。实验是可复制的游戏环境，不是编程代理。

分叉买到的，常常是同一步的另一次随机结果。

**链接：** [原文](https://arxiv.org/abs/2611.13003)

### Trending Open-source Projects

#### 1. Astryx

人和代理一起改界面时，组件约定常常藏在某人的习惯里。代理每次都要重新猜属性名、主题该怎么覆盖、文件该放哪。一套给人用的组件库，如果命令行和文档不是同一份约定，代理就只能对着网页文档猜。

Astryx 是 Meta 开源的 React 设计系统，仍在 Beta。组件、主题和命令行放在同一套命名下。样式在内部用 StyleX 写，调用方看到的是预先构建的 CSS 和带类型的 React 组件，不必再装一套构建插件。主题是一组 CSS 变量，改外观不用把组件源码包一层。命令行可以列出组件、做脚手架和换主题。项目自述它在 Meta 内部长了八年，并服务过大量应用；这个使用规模没有独立核对。本次用 GitHub API 读到 26,614 star、2,066 fork，MIT，最近一次推送是 11 月 13 日。它出现在当日总榜和 TypeScript 日趋势里，总榜页面写着约 1,830 stars today。页面上的累计星数与 API 相差几颗，是两次读取的时间差。

它把同一份组件约定同时交给人和代理。Beta，而且“代理会不会因此少猜错”这次没有用任务测过。

**链接：** [GitHub](https://github.com/meta/astryx)

#### 2. SkillEvaluator

技能文件夹写着代理该怎么做，但看不出它是在帮忙，还是只是把说明写长了。安装前的安全扫描回答的是有没有危险写法，回答不了装上以后任务有没有变得更好。

SkillEvaluator 把检查分成三层。第一层不调用模型，用规则给技能打质量分；仓库自带的示例在无密钥时给出 84.5/100，这是这个示例的分数，不是一组技能的评测。第二层看说明是否自相重复，也可以对一套技能目录做重叠比较。第三层在默认的 Docker 沙箱里，比较带上技能和不带技能的实跑。它和已经介绍过的 SkillSpector 接在同一条技能流水线里，但量的是行为变化，不是漏洞特征。本次用 GitHub API 读到 880 star、106 fork，Apache-2.0，最近一次推送是 11 月 13 日。它出现在当日 Python 趋势列表里，页面写着约 108 stars today。仓库链到 2026 年 8 月的一篇预印本，本日报不把那篇旧文再讲一遍。

它把“技能有没有改变行为”收成可以放进 CI 的对照。实跑依赖可用的代理和沙箱，静态分高也不等于任务会更好。

**链接：** [GitHub](https://github.com/NVIDIA/SkillEvaluator)

#### 3. TensorFold

本地把模型跑起来，常常要先装 Python 和一整套推理库。换一台机器，或者让代理自己起服务时，这套依赖本身就会失败。

TensorFold 是一个 Zig 写的服务进程。它直接读检查点，在 Apple Silicon 上走 Metal，在 NVIDIA 上走 CUDA，服务时不再要 Python 或 MLX。快速开始把 Qwen3.5-2B 的 4-bit 检查点钉在一个修订号上再启动。仓库还要求贡献者用 Agent Traffic Control 认领问题，避免多个代理改同一处；那个配套仓库本次只有 46 star，不能当成已经广泛采用。本次用 GitHub API 读到 TensorFold 1,954 star、393 fork，Apache-2.0，最近一次推送是 11 月 13 日。它出现在当日总榜，页面写着约 54 stars today。本日报没有重跑速度，也没有和 llama.cpp 并排比较。

它把本地推理收成一个不依赖 Python 的二进制。速度和数值是否对齐，还要另测。

**链接：** [GitHub](https://github.com/ashhart/TensorFold)
