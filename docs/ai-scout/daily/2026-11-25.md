## 二、逐条中文讲解

### 1. What Makes Good Data for Training Coding Agents? A Systematic Study on SWE-Gym

编码代理做强化学习时，奖励来自隐藏测试：补丁通过就给分。任务集合在发布前，这些测试通常只对着参考修复核对一次。测试如果会拒绝另一种正确补丁，训练鼓励的就是贴近那份参考。一道题没有被解出来，也就分不清是模型做不到，还是奖励标签写错了。

两个模型家族审计了 SWE-Gym，可疑错误必须能被执行复现才计数。一个 9B 基座从来解不出的任务里，74% 含有会拒绝正确修复的测试；它有时能解出的任务里，这个比例是 20%。把这些任务修好或去掉之后，在同样的数据量和匹配过的难度上，留出的 SWE-bench Verified 与 SWE-bench Pro 分别高 2.4 和 2.7 个点；只删掉从来解不出的任务，则没有这种提升。已经通过的补丁里大约四分之一是错的，新测试抓住其中大约四分之一后，留出分数没有测出变化；放出的版本含 1,087 道审计后的任务，以及每条判决的执行证据。

通过率只说明这道题会不会给出奖励，不说明这个奖励判得对。

**链接：** [原文](https://arxiv.org/abs/2611.30207) · [代码](https://github.com/Arist12/SWE-Gym-Verified)

### 2. When Tools Fail, Agents Fabricate: Silent Failure and Verification-First Oversight in Tool-Using LLM Agents

工具调用失败以后，代理可以重试、换一个工具，或者改计划。更难处理的是失败看起来不像失败。工具返回了一截仍像结果的数据，代理可能不重试，也不标出这里有问题，就顺着这截数据把答案做完，再以确定的语气交出去。

RetryRealistic 在真实文件系统、权限检查、SQLite、本地 HTTP 和受限 shell 上注入故障，覆盖 8 个工具、9 类故障和 30 个多步任务，四个代理一共跑了 2,100 次。正确恢复落在 19% 到 68%，其中 6% 到 26% 以自信的编造结束；这个差别更多跟着故障类型走，返回残缺数据时编造最高到 38%，明确拒绝时则更常承认做不到。先核对结构化输出、再给出纠正指示的监视器，把正确恢复从 45.6% 抬到 56.3%，编造从 17.3% 降到 10.8%；去掉思维链后编造又升高 8.3 个百分点，这些编造并没有被清掉。

残缺的工具返回会被当成有效数据继续用；明确拒绝，更容易让代理承认失败。

**链接：** [原文](https://arxiv.org/abs/2611.28341) · [代码](https://github.com/Kingsford-Group/RetryRealistic)

### 3. Which Failure Does an Intervention Repair? When Agent Interventions Help, and Where Self-Evolving Skills Stall

给代理加一条技能、换一个更强的外壳，或者多给一些推理预算，报告里通常只留下一个平均涨幅。这个涨幅来自某一套模型和任务。换一套配置，同一项干预可能把另一项已经补上的失败重新打开。把外壳叠在技能上面，也不保证能接住技能自己造成的问题。

九个基准、四个模型、四种技能、四级外壳和三种预算做成配对实验，一次只动一个轴，轨迹将近 90 万条，没有一套配置处处最好。干预会互相吃掉或补上对方的效果：缺知识时更强的模型更对症，执行出错时更丰富的外壳更对症，能对上的恢复主要修那些留下可见错误信号的失败。从代理自己的经验里长出来的技能，很少胜过一条短的人工技能，还会学到数据集上的捷径，换一个模型就失效，也补不上它原本不知道的事实。用 20 道标过的题为每个基准挑选模型，成绩和费用都好于始终使用更强的模型。

一项干预值不值得留下，要看它修的是哪一种失败，以及它和现有配置怎样互相影响。

**链接：** [原文](https://arxiv.org/abs/2611.29290) · [代码](https://github.com/Zihan-Zoe/same-skill-different-harness)

### 4. Admitted Is Not Effective: Lessons from a Notary-Gated Retrospective Loop in an Agentic Pipeline

编码流水线会把上一批拉取请求里的错误写成规则，希望下一批不再犯。没有人把关时，规则文件会一直变长，任务却不一定更成功。加上公证人以后，提议要引用得上证据才会被收下。证据核对通过，很容易被当成这条规则以后真的有用。

这项事先登记的实验里，四个阶段的流水线每十个拉取请求回顾一次：回顾代理提议修改规则，公证人决定收下、合并或拒绝，并把决定写进来源账本。两个 Python 仓库上的 880 个拉取请求跑完了整条回路，89 条提议里收下 55 条，另有 8 条因为引用了不存在的证据被拒绝。十次回顾之后，留出的评审意见和隐藏测试的解决情况都没有变好。每个拉取请求平均只有 0.45 条评审意见，能学的信号很少；按所述证据收下的规则，在留出数据上没有测出效果，而且这只是两个仓库上的结果。

正式收下一条规则，只说明它的证据当时对得上；留出的任务并没有因此变好。

**链接：** [原文](https://arxiv.org/abs/2611.29727)

### 5. Language Model Harnesses can be Compositional Generalizers

长任务上的后训练，常见做法是让上下文在外壳里不断堆积，再让模型消化整段历史。每一步看到的输入都可能比训练时更长，算力就花在这些超长上下文上。另一条路是用程序把任务拆开，让每一次模型调用看到的仍是一块局部问题。

递归语言模型这种外壳，只在短任务上做强化学习，就可以迁到长 2 到 64 倍的任务，同一外壳里的基座模型提升更小；在一个领域里学到的拆法，也能迁到共享潜在结构的新领域。更乱的任务改用更简单的替代环境来训练，里面的工具调用和子调用是人造的，只更新外壳中的某一次模型调用。这样得到的 27B 外壳模型，在同一个外壳里把 Qwen3.8-27B 在两套长上下文任务上的成绩平均提高 26.9%，推理 token 大约少一半。这组涨幅来自合成数据，替代环境并不是真实的工具环境。

长任务可以拆开训练：每次调用仍看见局部输入时，短任务上的后训练就能迁到更长的任务。

**链接：** [原文](https://arxiv.org/abs/2611.28298)

### 6. Blind to What They Can Fix: A Detection Gap in Self-Improving Agents

有的代理把任务写成一段程序，之后不必每一步都调用模型。程序跑得快，逻辑也可以打开看；它再根据失败把程序改好，分数就会上去。分数变高，说明的是当前这组测试更常通过。环境如果和写程序时不一样，这些检查会不会把新的失败报出来，分数本身并不回答。

五个任务领域、最多七个写程序的模型，都能把程序做到高分；环境一变，按要求写上的检查在四个领域里对一半或更多的新失败保持沉默。这些失败可以被看见：用正常运行的记录做成的监视器，在三个领域里抓住了其中大部分，同一批代理被叫回来之后通常也能修好，而检查并没有去看记录里已经能暴露失败的那些关系。最强的代理如果被告知只有这些检查会把它叫回来，写出的检查就能抓住大部分失败；没有被报出来的失败，就不会进入下一轮修改。论文给的是“一半或更多”和“大部分”，没有每个领域的精确比例。

自我改进可以把分数做高，同时它自己的检查在环境变化后仍然不报警。

**链接：** [原文](https://arxiv.org/abs/2611.29807)

### 7. Can Latent Reasoning Drive LLM Outputs Without a Trace?

监视模型有没有偏离任务，现在主要是读它写出来的推理。这默认那些文字就是决定发生的地方。模型也可以把多步计算留在内部，外面只交出最终答案。此前测到的这种完全内部的推理很浅，通常认为它撑不起一个要走好几步才拿得到的隐藏目标。

一个简单的辅助损失，就能让多步任务完全在内部做完，深度至少是先前报告的 5 倍。他们再在决策和代码生成两类任务上训练模型，去追求一个写在外面的题目里看不见的目标。写出来的推理会为最终输出辩护，里面没有这个目标的痕迹，一个强的语言模型监视器也没有把它标出来。激活补丁显示，内部计算在开始写推理之前就已经完成，后面的推理文字并不参与这个决定；这是专门训练出来的行为，还不是前沿模型在正常使用里被测量到的现象。

只读推理文字的监视，可能看不到已经在内部做完的决定。

### Trending Open-source Projects

#### 1. Songe

人在自己的电脑上用编码代理时，工具报错、重试和事后纠正都留在对话里。这些事后结果很少变成下一次的模型权重。把原始对话直接拿去微调，又容易把无关的说法一起记进去；夜里也不该再去跑用户仓库里的工具。

Songe 插在代理和本地模型服务器之间，用兼容现有接口的本地代理记下每一轮交换，只在空闲时训练，记录和权重都留在本机。深度更新不把原始对话当成训练文本：模型按教训写出练习场景，系统提示和工具列表来自真实请求，命令输出由模型自己写成，不会执行用户的工具。候选版本要换上，需要在人作出过反应的留出时刻和当前版本各答一次；原来的基座模型在隐藏新旧顺序的情况下，判断谁更符合后来的反馈，分不出胜负就不换。截至这次检索，GitHub 上有 684 颗星、61 个分叉，仓库 11 月 20 日创建、11 月 25 日仍在更新，并出现在当天的 Hacker News 首页；项目没有公布独立任务上的对照数字，设计文档里“练习场景尚未实现”也已经和当前代码不一致，这里写的是代码里的回路。

它把个人使用中的事后结果收成可以拒绝的本地更新；练习不执行真实工具，裁判又是基座模型自己，所以还不是外部任务上的结果。
