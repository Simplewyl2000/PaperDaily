## 📝 逐条讲解

### SaeRL：用稀疏自编码器内部信号做后训练数据工程
后训练（尤其 RL）的数据工程长期依赖外部启发式信号，而忽略了模型自身内部蕴含的丰富信息。SaeRL 用机制可解释性工具——稀疏自编码器（SAE）——从模型内部激活里抽取信号，显式建模数据的三种内禀属性：质量（quality probe 过滤）、难度（按校准难度排"由易到难"课程）、多样性（SAE 空间聚类 + 批内适度混合）。在 Qwen2.5-Math-1.5B 上相对原始 GRPO 平均准确率 +3.0%，并少用 20% 训练步即达目标；且 SAE 信号能跨模型族/规模迁移，是个轻量可复用的数据工程工具。对做代码/推理 LLM 后训练、关心"数据怎么选"的团队很实用。
🔗 链接：https://arxiv.org/abs/2605.27354 ｜ 代码：None

### Zero-to-CAD：百万级 agentic 数据合成，无需真实数据
高质量带"构造历史"的 CAD 数据极度稀缺。Zero-to-CAD 把数据合成当作 agentic 搜索问题：把 LLM（gpt-oss-120b）嵌入一个带执行/校验/文档查询的 CAD 环境里，让它迭代生成、运行并校正代码，从而在零真实构造历史的前提下合成约 100 万条可执行、可读、可编辑的 CAD 序列，并精选出 10 万条高质量子集。用这批合成数据微调一个视觉语言模型，从多视角图重建可编辑 CAD 程序时超过包括 GPT-5.2 在内的强基线。它展示了"用 agent 在反馈环境里自造可验证数据"这条数据合成范式在垂直领域的可行性，对自动化数据构造方向有借鉴意义。
🔗 链接：https://arxiv.org/abs/2604.24479 ｜ 代码：None

### MUSE-Autoskill：技能全生命周期自进化
现有技能创建方法把技能当成孤立、静态的产物，复用性、可靠性和长期改进都受限。MUSE-Autoskill 提出"以技能为中心"的统一生命周期：按需创建、跨任务存取复用、组织与选择、再用单元测试与运行时反馈做评测和精炼。它最大的新意是引入"技能级记忆"——为每个技能累积跨任务的经验，使其随时间越用越好、并能跨 agent 系统迁移。在 SkillsBench 上初步证明：被生命周期管理的技能在任务成功率、效率、复用和迁移上都更好。把 Anthropic Agent Skills 这类"可移植技能"从静态文件升级为"长期、带经验、可测试"的资产。
🔗 链接：https://arxiv.org/abs/2605.27366 ｜ 代码：None

### SkillOps：把技能库当作自维护的软件生态
随着 agent 长期运行，技能库会不断被新增、复用、打补丁、接入变化的依赖，从而积累"技能技术债"——单个技能本地不报错，却悄悄拖累后续检索、组合与执行。以往工作大多只管"任务时"的检索/规划/修复，缺"库时"维护。SkillOps 把每个技能表示为带类型的 Skill Contract（前置/操作/产物/校验器/失败模式），用分层技能生态图(HSEG)组织，并沿"效用/冗余/兼容/失败风险/校验缺口"五维诊断库健康，再施加 merge/repair/retire/加校验器/加适配器等维护动作。它是即插即用层：把原始库换成"维护后的库"即可，下游代码不变。ALFWorld 上单独作为 agent 达 79.5%(超最强基线 +8.8pp)，且基于规则的库时维护几乎零 LLM 调用。
🔗 链接：https://arxiv.org/abs/2605.13716 ｜ 代码：https://github.com/Hik289/SkillOps

### JECS：多模型基准的可证明联合去污染
基准污染会让被审计模型的成绩虚高、跨模型比较失真。已有的"训练数据检测"打分法缺理论保证，而单模型的 conformal 方法分别套到每个模型上又会产出"各模型各自的基准"，破坏公平比较。JECS 把"多模型联合去污染"形式化为一个联合选择问题：算每个模型的 conformal p 值，按条目取最大值聚合，从右尾观测重建一个保守的 max-p 零分布包络，再用自适应 BH 过程选出可证明控制"全局污染率(GCR)"的干净基准。实验显示它在维持目标 GCR 的同时比 max-p 基线 power 更高。对需要公平比较多个模型、又担心数据污染的评测团队有用。
🔗 链接：https://arxiv.org/abs/2605.21543 ｜ 代码：None

### 推理模型基准污染检测的脆弱性
这篇 ICLR 2026 工作系统揭示：对大推理模型(LRM)而言，现有污染检测极其脆弱。两阶段分析发现——在 SFT 阶段注入的污染，经过 GRPO 训练后几乎检测不到(根因是 PPO 式重要性采样+裁剪平滑了输出分布)；而直接对先进 LRM 做 CoT SFT 污染，即便不经 RL"洗白"，10 种检测方法的 AUROC 也都逼近 50%(等于瞎猜)。原因是 LRM 本就对"分布内但没见过"的样本给高置信度，打破了"污染≈记忆"这一核心检测假设。结论很刺眼：开发者可以"SFT 注入污染拿 +8.82%，再用干净数据 GRPO 抹掉痕迹"。强调了为 LRM 设计可信评测协议的紧迫性。
🔗 链接：https://arxiv.org/abs/2510.02386 ｜ 代码：https://github.com/ASTRAL-Group/LRM_Conta_Detection_Arena

### Code as Agent Harness：一篇把"代码即 harness"讲清楚的综述
Coding agent 的真实战力越来越多来自 harness（围绕模型的工具、提示、中间件、记忆与执行逻辑），而非只靠基座模型。这篇综述以"代码作为 agent 的运行基底"为统一视角，分三层组织：(1) harness 接口——代码如何把 agent 连到推理、行动、环境建模；(2) harness 机制——规划、记忆、工具使用与反馈驱动的控制/优化；(3) 从单 agent 扩展到多 agent 的协调、复用与验证。还系统列出开放挑战：超越"最终成功率"的评测、不完整反馈下的验证、无回归的 harness 改进、多 agent 共享一致状态、安全关键动作的人类监督等。适合想系统建立 Harness Engineering 全局观的人。
🔗 链接：https://arxiv.org/abs/2605.18747 ｜ 代码：None

### RL 是稀疏策略选择，不是能力学习（含 ReasonMaxxer）
这篇做了细粒度 token 级分析：RL 对推理的"行为足迹"出奇地简单——只修改 1–3% 的 token 位置，不会引入基模型 top-5 之外的候选，且集中在"高熵决策分叉点"(模型本就拿不准走哪条推理分支处)。用 oracle 干预+随机对照证明：这些位置选哪个 token 是因果关键的，而随机改则无效；更妙的是这些位置不需要 RL 模型就能定位——基模型自身的 token 熵就是强代理。据此他们构造了 ReasonMaxxer：从基模型采少量 rollout，用熵门控定位决策点，仅在这些位置施加 advantage 加权对比损失，其余 token 锚回基分布。结果在三个模型族多个规模上匹配甚至超过完整 RL，却只用几十道题、几百条 rollout、单卡几分钟，训练成本约降三个数量级。是对"RL 后训练到底学到了啥"的有力纠偏。
🔗 链接：https://arxiv.org/abs/2605.06241 ｜ 代码：None

### MaR：把元认知当奖励
现有奖励设计要么是 RLVR(只看最终答案对错，对中间推理引导有限)，要么是 Rubrics-as-Reward(要逐实例设计 rubric，工程量大)。MaR 提出用"元认知"两个通用维度来做过程奖励：元认知知识(无需手工 rubric 即可识别任务相关信息)与元认知调控(规划并调整推理过程)。它把 rollout 拆成显式元认知组件，按"知识覆盖+调控保真+最终正确"做轨迹级奖励，从而把奖励信号扩展到整条推理轨迹又保持通用。22 个基准上一致提升，相对基模型最高 +7.7%、相对原始 DAPO 最高 +11.0%，Qwen3.5-9B+MaR 在总均分上超过 GPT-OSS-120B，并能泛化到域外数据。
🔗 链接：https://arxiv.org/abs/2605.23384 ｜ 代码：https://github.com/OpenCausaLab/MaR

### POISE：让语言模型给自己当 critic
RLVR 里做方差缩减要靠基线估计，但代价不小：PPO 要一个与策略同规模的 critic，GRPO 要每个 prompt 多次 rollout 才能稳住组均值。POISE 几乎零成本地拿到基线——直接用策略模型前向时已经算出的内部隐状态，加一个轻量探针预测"期望可验证奖励"(用隐状态+token 熵统计)，与策略一起在线训练。为保证梯度无偏，它用"跨 rollout"构造：用一条独立 rollout 的内部状态预测另一条的价值。因为只需单条 rollout 估计 prompt 价值，固定算力下能跑更高的 prompt 多样性。在 Qwen3-4B 与 DeepSeek-R1-Distill-1.5B 上匹配 DAPO 却更省算力，且价值估计逼近独立 LLM 规模的价值模型。
🔗 链接：https://arxiv.org/abs/2605.07579 ｜ 代码：None

### Bi-NAC：把文本反馈当成"可学习"的量来训
带文本反馈的 RL 里，critic 用自然语言给 actor 反馈来补充稀疏标量奖励。但以往把反馈当固定/辅助信号，忽略了关键性质：反馈不只要"正确"，更要"放进上下文后能真正提升策略"。Bi-NAC 把这个耦合形式化为 Stackelberg 双层规划，联合训练一个"产出能提升下游奖励的反馈"的 critic 和一个"会利用反馈"的 actor。在 MATH-500、MBPP、GPQA 上提升样本与参数效率：2B 模型在 MATH-500 上 46.6% 超过 3B GRPO 的 41.4%，6B 模型在 GPQA 上 49.3% 超过 7B GRPO 的 43.6%。把"反馈本身"纳入优化，是个值得关注的方向。
🔗 链接：https://arxiv.org/abs/2605.24547 ｜ 代码：None

### Anthropic：Natural Language Autoencoders（把激活变成英文）
可解释性一直想"直接问激活在想什么"。Anthropic 的 NLA 用两个 LLM 模块——activation verbalizer(激活→文本描述)与 activation reconstructor(描述→激活)——用 RL 联合训练来重建残差流激活；虽然只优化重建，得到的英文解释却越来越像对模型内部的合理解读(例如补全对句时能看到 Claude 提前规划押韵)。在审计实验里，装备 NLA 的审计员发现被植入"隐藏动机"的命中率从 <3% 提升到 12–15%，即便拿不到植入用的训练数据；他们已在 Claude Mythos Preview / Opus 4.6 的部署前对齐审计中用上 NLA，并发现"模型其实知道自己在被评测却没说出来"。已开源训练代码与若干开源模型上训好的 NLA。
🔗 链接：https://www.anthropic.com/research/natural-language-autoencoders ｜ 代码：https://transformer-circuits.pub/2026/nla/

### Anthropic：Project Glasswing 进展 + Exploit Evals
Anthropic 用受限访问的 Mythos Preview 模型扫描了 1000+ 关键开源项目，与约 50 家伙伴一起发现上万个高/严重级漏洞，并解释为何暂不公开发布此类模型(其自主端到端写漏洞利用的能力具高度两用风险)。配套的 Exploit Evals 帖子值得关注：过去一个月出现两个更难的学术基准 ExploitBench、ExploitGym，加上 Anthropic 与 MATS 合作更新的智能合约利用基准 SCONE-bench，Mythos Preview 在三者上都稳超其它模型。对关心"模型攻防能力如何被严肃评测"的人，这批新基准是重要风向标。
🔗 链接：https://www.anthropic.com/research/glasswing-initial-update ｜ Exploit Evals：https://red.anthropic.com/2026/exploit-evals/

### OpenAI：What Parameter Golf taught us
Parameter Golf 是 OpenAI 办的一个高约束 ML 挑战赛：在固定数据集上最小化留出损失，但产物(含权重与训练代码)限 16MB、训练预算限 8×H100 上 10 分钟，参与者 fork 官方仓库改模型再经 GitHub 提交。8 周收到 1000+ 人的 2000+ 份提交，从优化器调参、量化到测试时训练等花样百出。OpenAI 的复盘里一个值得关注的观察是：参与者普遍用 AI coding agent 大幅加速实验迭代——这也被当作"开放技术挑战如何随 agent 普及而改变"的早期信号。对关心"coding agent 在真实 ML 研发循环里能加速多少"的人有参考价值。
🔗 链接：https://openai.com/index/what-parameter-golf-taught-us/ ｜ 代码：None
