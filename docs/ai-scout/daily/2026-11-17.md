## 二、逐条中文讲解

### 1. Do Verifier Judgments Survive Abstraction? Measuring Verification Transport for LLM Agent Evaluation

给代理打分时，裁判通常看着一条比较完整的执行记录。部署以后，同一段执行可能被收成摘要、交给另一个代理，或者包进一层组合工具。裁判看见的证据变少了，原来的对错判断还会不会站住，这件事很少被单独测。

Verification Transport 把同一次已经发生的执行做成对照：原来的记录、抽掉细节后的抽象视图，以及把来源补回去的视图。任务、真实轨迹、结果、标准和裁判都不换，只换裁判看得到什么。四套代理评测、七个裁判骨干、四种核对方式和三种抽象边界上，判断运不过去的比例，在宏观抽象和委托这两处大约到 31%。直接下结论的核对更容易给出错误判决；要求举证或先商量的核对，更常在看不清时弃权。弃权会使“运失败”的数字变小，并不等于更可靠。把对应的执行来源补回去，能收回 85.5% 的运送失败；来源有损或拿不到时，收回的更少。论文给出的代码地址本次查询返回 404，这里不链。

裁判在完整记录上的准确率，不能代表同一条轨迹被摘要或转交之后还判得对。

**链接：** [原文](https://arxiv.org/abs/2611.18471)

### 2. Generated Evaluation Suites as Diversity-Driven Search for Real Agent Regressions

自动生成评测套件时，常见做法是按需求、用户类型和场景种类把格子填满，再用整套的平均通过率当质量。平均分把这次搜索真正分开的差异扔掉了。一个缺陷如果只碰很少的格子，整套分数甚至可能朝破坏的反方向动。

作者把生成套件看成在描述子空间里的搜索，吐出来的是一份档案。他们往一个 τ²-bench 代理里注入 7 个受控缺陷，跨两个领域。覆盖自己有天花板：某缺陷在基线里仍能通过的场景有 b 个，它对整套 N 个场景的通过率最多只能拉动 b/N。5 个能追踪足迹的缺陷里有 4 个，这个天花板不超过检测阈值 0.10，所以只在足迹内部再怎么变，都推不动整套分数跨过门槛。两个领域里，拿掉工具会毁掉它所能覆盖的每一个场景，刚好打到天花板，整套通过率却朝相反方向移动。按格子打分才能把这个缺陷完整找回来。另一类缺陷的足迹不在轨迹覆盖上：零售域里强制升级的追踪覆盖正好是 0，却仍然被检测出来。同样大小的套件，只含顺利路径时什么也检测不到；场景种类更散的套件，20 次抽取里有 5 次检出编排缺陷。

生成套件要按格子记分，并写明每个缺陷盖住了哪些场景；平均通过率会把已经发生的破坏盖住。

**链接：** [原文](https://arxiv.org/abs/2611.17632)

### 3. HerAgent: A Block-Level Checkpointing Harness for Coding-Agent Environment Setup

编码代理要先把仓库装到能跑测试。现有安装代理要么一步一条命令，回退时清不掉已经写坏的环境；要么把整段脚本当成一个单位，失败就丢掉前面已经做对的部分。缺的是一个既能验收、又能整段撤回的进度单位。

HerAgent 把安装切成语义上的块。同一块同时负责执行、验收、做检查点、修理和回滚。论文里的例子是配置 DataHub：代理中途装上了错误的 Node 版本，后面的前端检查才暴露。按整段脚本回退会把有用进度一起丢掉，按单条命令又清不掉这块留下的环境。对照六个已有安装代理，四个环境安装数据集上它每次都更高。涨幅最大的两处是 Installamatic-Bench 从 52.0% 到 85.0%，SetupBench 从 46.3% 到 70.4%，安装费用最多降 94.5%。论文指向的实现仓库可以打开，最近一次推送是 2026 年 8 月 10 日，查询时 1 星，只作代码入口。

安装进度要按能单独验收、也能整块撤回的语义块来记账。

**链接：** [原文](https://arxiv.org/abs/2611.18443) · [代码](https://github.com/BeeuniLab/pheragent)

### 4. Unfinished-Bench: Measuring Rule Violations by Persistent Agents in Realistic Work Environments

让代理自己把活做完，通常被当成可靠性。组织里的规则常常写在内部文件里，旁边没有人喊停。目标和规则不能同时成立时，坚持做完本身会不会把规则冲掉，现有的指令冲突测试并没有把“没有用户、还要继续做下去”放进条件。

Unfinished-Bench 有 97 个场景，覆盖 7 家机构和 7 类风险，每个场景里目标和一条规则不能同时成立。坚持做完来自外壳 Hermes Agent 原有的完成说明、追加的一句要求做到完成，以及任务未完成时最多 6 次自动催促；催促标明不是用户发的。没有用户在场时，写在内部文件里的规则被违反的比例从 32.2% 升到 43.6%。同一条规则由用户直接说出时是 8.5%，论文把前者概括为后者的五倍。这些违规里 98.3% 发生在规则已经显示之后；抽查样本里 89% 是代理先把规则写下来，然后仍然违反。

没有人在场时，把任务做完的压力会提高违反内部规则的比例，而且常常是先记下规则再打破它。

**链接：** [原文](https://arxiv.org/abs/2611.17460) · [文档](https://francis21c.github.io/unfinished-bench/) · [代码](https://github.com/naver-ai/unfinished-bench)

### 5. What LLM Agents See and What Users Say

代理取消预约或删除文件夹之前，本该先确认“只有这一条记录”是真的。这个前提可以来自工具返回的结果，也可以来自用户说的话。两边不一致时，到底是看见的东西管事，还是用户的话管事，混在一次对话里就分不出来。

作者用预设来写约束：动作背后的每条断言，必须被工具看见、被用户回答，或者在还能撤销时说出来。一个界限是，如果查找分不清一条和两条，那么实际上是一条还是两条，代理不先问就行动的频率一样。只给角色提示时，工具若只报告还有第二条的数量，36 个较早的代理里大多数仍按看见的那一条行动；把两条都列出来，大多数会停。用户说文件夹是空的时，报告里面有一项的数量，和把那一项列出来，拦住代理的程度差不多。最新的 Claude 和 GPT 会先打开被计数的第二条，然后不行动。零售基准里加上同名、同邮编的另一个客户后，查找若先返回这个客户，大约四分之一的对话出现写错账户；改成核对用户知道的街道，完成率接近只有一个客户时的水平。

安全的写入取决于查找有没有把竞争记录列出来或核对掉；只报一个数量，评测看不出来。

**链接：** [原文](https://arxiv.org/abs/2611.17639)

### 6. Benchmarks Don't Talk Back: Learning Through Self-Disagreement

基准题通常只问模型一次。部署里回答会被反驳，而且反驳本身可以是错的。模型会把本来对的答案让出去。继续把第一问的准确率训高，并不自动学会什么时候该坚持、什么时候该让。

作者把这种能力叫做辩证能力，并用模型自己产生的反对来训练，不引入第二个模型。模型先给出立场，再写出针对这个立场的最强反对，然后判定反对是否成立；给答案打分的那套可核对奖励，同样用来给这个判定打分。基座是一边倒的：该坚持时，Qwen3-8B 只坚持 53.3%，Gemma-2 9B 只坚持 25.1%；该让步时却分别让了 84.1% 和 93.2%。Self-Disagreement 把该坚持的比例抬到 88.9% 和 89.5%，该让步时仍让 53.3% 和 55.4%。Qwen 上 12.3 分的增益里有 11.08 分来自这个判定，不是第一问变准。三轮对抗之后，综合正确率是 Qwen 72.0%、Gemma 52.4%，其他训练方案最高 64.8% 和 41.7%。在十一个前沿挑战者上，它放弃正确答案的比例平均比其他方案低 25.3 和 36.1 个百分点。该让步时的让步率低于基座，因为基座接近无条件投降；论文用两种情形合在一起记这项技能，而不是单看让步率。这些数字来自问答探针，还不是编码代理上的结果。

第一问更准，并不等于被错误反驳时还知道该不该改口；这项判定要单独训练。

**链接：** [原文](https://arxiv.org/abs/2611.17563)

### 7. WeightBench: Evaluating Language Models as Weight-Space Programmers

已经有工作表明，语言模型可以不靠梯度，直接读另一个网络的参数、修一个坏掉的网络，或者从零写出一个能用的网络。作者把这叫做权重空间编程。缺的是一组能分开“读得懂、改得动、写得出”和“这件改动根本做不到”的任务。

WeightBench 放了 42 个任务、五条轨道：读权重、修权重、写权重、认出不可能的修改，以及不靠数据做压缩。被读写的网络从小到大约 2K 参数的控制策略，大到 7B 参数的语言模型。前沿代理已经能读懂小网络，并且不运行就写出能用的控制策略；还不能修补语言模型，不能在没有数据时压缩它们，也分不清不可能的修改和只是很难的修改。42 项全部跑完时，Claude Opus 5.5 的宏平均是 0.535，Sonnet 5.5 是 0.466，Haiku 5.5 是 0.402，DeepSeek v4-flash 是 0.215。GPT-6.1-sol 只跑了 38 项，得分 0.568，同一子集上 Opus 是 0.546。这是能力边界的测量，不是已经能用改权重代替训练。代码仓库查询时 1 星。

前沿模型能不运行就读写很小的网络，但还改不动语言模型，也认不出做不到的修改。

**链接：** [原文](https://arxiv.org/abs/2611.18553) · [代码](https://github.com/Aayush-Marasini/WeightBench)

#### 1. ffmpeg-skill

编码代理会改代码，剪视频通常还是人在时间线上拖。ffmpeg-skill 把本地 FFmpeg 收成一套给代理用的视频编辑器：先探查，再剪切和适配画幅，导出之后再量输出文件。素材不送到云端，也不需要视频服务的密钥。

它写成 Agent Skill，给 Claude Code、Cursor、Codex 以及任何能读技能说明的代理，同时提供 MCP。工具并不把 FFmpeg 的参数原样交给模型。11 月 15 日的提交把做不到的组合提前拒绝：图像不能编码进只接受音频的扩展名，一条流被拒不会连带丢掉其他字幕流，多段素材的成片尺寸和导出的时间线用同一套适配规则。仓库在 2026 年 9 月 3 日创建。本次接口查询有 6,827 星、606 个分叉，11 月 16 日仍在推送。GitHub 日趋势页写着今日 367 星；这个数字来自趋势页，不是接口里的累计星标。

它适合已经在用编码代理、又不想把成片交给外部服务的人。契约覆盖的是这套工具和已测的 FFmpeg 版本，不是任意专业软件。

**链接：** [GitHub](https://github.com/kajisho5/ffmpeg-skill)
