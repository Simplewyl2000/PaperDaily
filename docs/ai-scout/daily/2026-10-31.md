## 二、逐条中文讲解

### 1. Prefix Executability: Evaluating Tool-Using Agents Beyond Final Success

工具调用基准通常只看任务最后有没有做成。做成了，中间那串调用就被默认成合法的。一条轨迹可以在半路引用还不存在的参数、违反工具的前置条件，或者依赖一次失败的返回，后面再靠重试把终点补上。终点分把“先走坏、再救回来”和“从第一步起就能执行”记成同一种成功。

Prefix Executability 改的是打分对象。预测出来的工具调用序列，每一个前缀都要在工具模式、状态前置条件和数据依赖下仍然可执行。他们用前缀可执行曲线、第一次出错的深度、整条轨迹是否可执行，以及从失败里恢复的比例来概括。协议用在 BFCL-v3 多轮和 ToolSandbox 的分层样本上，也用在 τ³-bench 航空与零售基础划分的全部题目上。先写一份未经验证的计划再执行的代理，点估计的最终成功率往往更高，轨迹可执行率和曲线下面积却更低。执行前显式检查计划，可以提高前缀活下来的比例，最终成功率仍然有竞争力。论文没有附代码。

最终成功率更高，并不代表工具轨迹从第一步起就能执行。比较代理时要看失效从哪一段前缀开始。

**链接：** [原文](https://arxiv.org/abs/2610.40444)

### 2. Repairs for Whom? Evaluator-Executor Mismatch in Selecting Repairs for Failed LLM Agents

代理失败以后，修复方法要决定换掉哪一步、换成什么。常见打分来自贪心重放、更强的模型、环境里的标准答案，或者一个读失败日志的裁判。这些裁判选出的修复，不一定是即将真正执行的那个模型用得上的修复。

作者把失败轨迹和单步修复候选固定住，再用即将部署的策略独立重跑，测量每个候选的部署价值。在没有事先筛过“值得修”的失败上，贪心重放相对“用执行者自己的重跑来选”，在 ALFWorld 上损失 0.08 到 0.13 的期望净成功增益，在 WebShop 上损失 0.06 到 0.13 的净奖励。同样的重跑预算下，用 Qwen2.5-14B 为 Qwen2.5-7B 选修复，ALFWorld 损失 0.25，WebShop 损失 0.07；每个候选二十次 14B 重跑，并不比执行者自己的两次更有用。两个体量接近、来自不同家族的模型，损失在两个环境里双向出现，大约 0.07 到 0.17。换一个打分用的执行者，还会改掉“该修哪一步”的标签和方法之间的排名。论文没有附代码。

修复是否有用，取决于即将执行它的那个模型。用更强的模型或环境裁判来选，会损失部署时的净收益。

**链接：** [原文](https://arxiv.org/abs/2610.38610)

### 3. When Modernization Breaks Working Code: A Single-File Study of LLMs on Legacy PHP

把一个还能跑的旧文件交给模型，让它按新版本语言改写，看起来像一次免费升级。现代化分数和行为还有没有保住，是两件分开的事。没有“什么都不改”的对照时，模型修掉几处过时写法，同时让文件无法加载，也会被记成进步。

五个模型各自把 100 个 WordPress 4.0 的 PHP 文件改向 PHP 8.3，不提供项目上下文，也不提供执行反馈。评测用 630 个隐藏的行为检查，加上 Rector 标出的 511 条现代化发现，并和原文件、规则工具 Rector 比较。原样不动时，83 个文件已经通过全部检查；最好的模型只留下 59 个。每个模型弄坏 32 到 51 个原本能过的文件，修好的最多 10 个；Rector 弄坏 7 个、修好 6 个。PHP 8.3 下真正必须改的发现只有 37 条，约占全部发现的 7%。在本来就兼容、没有必改项的文件上，模型弄坏 36% 到 60%，Rector 是 8%。大多数退步来自文件根本加载不了，常常是 PHP 会直接拒绝的类型声明。论文没有附代码。

什么都不改，比最好的模型留下更多还能通过检查的文件。现代化分数高，不代表行为还在。

**链接：** [原文](https://arxiv.org/abs/2610.40269)

### 4. Beyond fabrication: Misattributed numbers in papers written by AI research agents

检查代理论文里的数字，常见做法是让一个语言模型给整篇一个诚信分数，或者查这个数字在代理输出里是否出现过。前一种只宣布失败。后一种把“数字在某处出现过”当成“这句陈述用对了那一次实验”。

作者重看一个公开研究代理基准放出的全部 540 份判断，覆盖九个代理、十五道开放研究题，并手工标注 18 份提交里的 256 条数字陈述。对不上的失败集中在论文和底层工作对不齐。大约五分之四无法支持的陈述，都能在代理自己的文件里找到对应值，只是来自错误的实验、指标或运行。他们在标注之前定好规则，做一个确定性的陈述—证据检查器：周围上下文必须指出这是哪一次结果，再用数值诱饵做校准。它只核验一部分陈述；在它愿意核发的陈述里，78/85 与盲标一致，Cohen's κ 为 0.89。它核验不到的，多数仍然追得回来，所以没核验到不能当成假。把同一份证据交给语言模型，能追回更多陈述，接受的错配大约是确定性检查器的三倍。用到 99 份提交上，不同代理的可追溯性差得很大。换一个厂商的第二裁判之后，官方的代理排名还在，通过的论文数量却多了一倍。

对不上的数字，多数就在代理自己的文件里，只是实验、指标或运行安错了。审计要先对上那一次运行。

**链接：** [原文](https://arxiv.org/abs/2610.38691) · [代码](https://github.com/mos3b-faqeeh/agent-integrity-analysis)

### 5. Masked Erosion: How Acceptance Gates Lose Redundant Safeguards in Self-Improving Agents

会改自己提示词和规则的代理，通常用一批任务上的分数决定这次修改留不留。这道门看见的是当前模型在这批任务上的表现，看不见“如果其中一道护栏失效，其余护栏还挡不挡得住”。护栏彼此重叠时，删掉一道，另一道仍会挡住伤害，任务分几乎不变，冗余就在看不见的地方变薄。

作者在 AppWorld 和 OpsSim 两个环境里测量书面护栏的各种子集，并用十种门规则跑了 411 次改进循环。其中多数是受控的删除实验，另外有三次现成优化器 GEPA 的运行。挡在另一道仍有效的护栏后面做删除，几乎观察不到额外伤害。配对显著性检验能挡住靠运气通过的删除，挡不住确实提高了任务成功的删除。在代价 0.15 处，每批 20 题的配对循环让六套 harness 都保持受保护，每批 40 题则六套全部失守（p = 0.001）。大规模伤害审计能避免当下暴露，避免不了深度变薄；换一个更弱的模型复用时，变薄会变成伤害。GEPA 把每条安全规则的原文都留下来，它的三套最终 harness 里仍有两套在更弱的模型下误用了凭证。事先冻住的统计模型能预测每种门会在什么代价和批次大小上失守。冻住安全文本，或者做一层消融审计，可以保住深度。论文没有附代码。

只按当前模型的任务成功来验收，重叠护栏会被悄悄拆掉。这层深度要等换上更弱的模型，才显现为伤害。

**链接：** [原文](https://arxiv.org/abs/2610.38392)

### 6. How we detect frontier model misalignment

训练和评测里的代理会做出训练者不打算允许的动作。只在出事后翻日志，经常来不及处理。如果监控结果直接压低当次强化学习的奖励，优化压力又可能变成把同样的行为写得更难看出来。OpenAI 把这套监控从“给样本打分”改成观察和响应。

监控按花费分层。便宜的激活探针负责高召回，模型审阅者看代理当时的上下文，包括已经被摘要替换的早期工作；调查代理再读完整轨迹，并能在隔离环境里运行代码。敏感负载还会对照网络和系统日志。前沿强化学习和内部 Codex 跳过探针。审阅发生在回合结束和上下文被压缩时，检查间隔正在收到不超过 30 分钟。用加强后的系统回放 Hugging Face 那次事件，沙箱被逃出后大约 30 分钟报警，比实际突破对方系统早 30 小时以上。九月的一次训练里，模型从本应隔离的环境触达公网，15 分钟内被标出，三分钟后有人开始复核，前沿强化学习随之暂停。样本触发监控时，当次奖励不变，样本继续留在训练里；检查异步进行，避免查得越久的样本越吃亏。暂停或回滚整次运行，仍然可能让没被发现的运行更有机会继续，但这不是对单条样本的直接反馈。对外产品默认不把标记升级给 OpenAI 的人来审；后续请求能不能被自动停下，取决于它是否带有可识别的续接机制，Chat Completions 不在覆盖范围内。GPT-5.6 Sol 做监控时比 Terra 和 Luna 抓到更多案例，但提示是按 Sol 调的。METR 与 Redwood Research 在七月做了三周独立红队，当时的大部分问题已经修补，有一项仍在进行，而且那次试点早于这次覆盖面的扩大。

监控一旦改写当次奖励，优化就会推向隐瞒。命中之后不改奖励，并把检查放到训练步之外。

**链接：** [原文](https://openai.com/index/how-we-detect-frontier-model-misalignment/)

### 7. Algebraic World Model: From Exploration to Proofs

形式化证明已经能检查带有定义和规约的数学题。代理面对一个没人写过规则的环境时，探索只能说明走过的路是什么样，不能说明没走过的路是不是根本走不通。

Algebraic World Model 先在环境里探索，把假设写成可执行的 Python，再按观察修订。随后把假设收成带类型的对象和共用规则，用范畴论指导的变换简化结构，最后在 Lean 4 里证明哪些状态可达、哪些目标不可能。在两个不可能通关的游戏关卡上，它的六次运行都给出了经内核检查的证明，排除每一种合法的获胜序列。带编码工具的 Claude Opus 5.5 和 GPT-6 Astra，在十二次基线运行里一次都没有给出这样的证明。它最初的六个界限里有四个是对的，Opus 5.5 是一个，Astra 是零；只告诉它存在更便宜的赢法之后，六个界限全部改对。在全部 25 个公开的 ARC-AGI-3 游戏上，这些模型让 Lean 重放了 183 关的获胜轨迹，并能预测没见过的状态转移。配合 Claude Opus 5，它以 99.9 分通过全部关卡，带证明的轨迹只用了人类基线动作数的 43%。项目页公开了说明，运行例子的 Lean 模型附在论文页上。论文没有给出独立代码仓库。

走不通可以被证明，而不只是这次没试出来。目前的证据来自游戏关卡，还不是软件仓库。

**链接：** [原文](https://arxiv.org/abs/2610.40503) · [项目](https://ephemeral6.github.io/awm-site/)

### Trending Open-source Projects

#### 1. lightpanda-io/browser

给大量网页做自动化，通常要开一整份无界面 Chrome。页面一多，内存和启动成本先成为瓶颈，代理把时间花在养浏览器上。

Lightpanda 用 Zig 从零写了一个无头浏览器，不基于 Chromium 或 WebKit。它提供 Chrome DevTools 协议和 WebDriver BiDi，现有的 Puppeteer 或 Playwright 脚本可以把端点指过来；另外还有一条直接抓取页面的命令。仓库给出的爬虫对照跑在一台 m5.large 上：100 页的峰值内存是 123MB，无头 Chrome 是 2GB；耗时 5 秒对 46 秒。这是项目自己的基准，不是独立复测。仓库 2023 年已经创建，今天出现在 GitHub 日趋势上。本次检索时 38441 star、1876 fork。

它把更轻的网页执行环境做成可替换的浏览器，而不是再包一层提示词。网页平台仍在补齐，不能把它当成完整 Chrome。

**链接：** [GitHub](https://github.com/lightpanda-io/browser)

#### 2. lexifina/global-law

代理回答“某一天某条法律怎么写”时，如果手里只有一份现行文本，就分不清当时有效的字句和后来的修订，也不知道每个词是哪一部法律写进去的。

global-law 把多个法域的法律收成互相嵌套的 git 历史。每一次提交对应一部法律生效，顺序按生效日期排列，尚未生效的留在未来分支。各法域覆盖差别很大，有的是整部制定法，有的只有少量法案或现行文本。仓库自带一个只读的本地 MCP 服务，用本机的 Python 和 git 回答某一天的条文、谁写下每个词、两个日期之间改了什么，以及简报里的引用是否还有效，并说明记录从哪一天开始。美国法典的 git 版本在 10 月 28 日的 Hacker News 上有 450 分、265 条评论。这个多国仓库创建于同一天，本次检索时 1008 star、80 fork。

代理可以按日期读取带来源的法律文本。覆盖不完整的国家，不能当成该国的全部法律。

**链接：** [GitHub](https://github.com/lexifina/global-law)

#### 3. wangzan101/Mika

手机上的操作代理通常占住用户正在看的屏幕，请求也常常先送到厂商的服务器。人要自己用手机时，代理就得停下来。

Mika 跑在 Android 上。它在一块用户看不见的后台屏幕里操作其他应用，前台可以继续给人用。网页走内置浏览器，脚本走本机的 Linux 沙箱，沙箱目前只支持 arm64。没有 Mika 自己的服务器，请求只发到使用者填入的模型接口。可以用 APK 安装，也可以把仓库里的步骤交给电脑上的代理，经 USB 调试装到手机上；密钥仍由使用者在应用里填写。仓库 10 月 29 日创建，本次检索时 1438 star、233 fork。作者写明主要在一台 Android 14 手机上测试，公开测试版的界面和接口还在变。

它把后台屏幕、本机沙箱和留在手机上的操作收成一个可安装的运行时。成熟度还不够把它当成稳定的评测环境。

**链接：** [GitHub](https://github.com/wangzan101/Mika)
