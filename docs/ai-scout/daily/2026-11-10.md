### 1. When Instruction Files Go Stale: Documentation Debt and Hidden Cost in Coding Agents

编码代理每次开会都会读仓库里的 `AGENTS.md` 或 `CLAUDE.md`。文件里写着怎么跑测试、代码在哪、添加一个组件要走哪些步骤。代码后来搬走了，旧路径还留在文件里。只看这次 bug 有没有修好，看不出代理多走了多少路，那一行也会继续留到下一次。

作者从三个还在维护的仓库里各取一条真实的过期指令，代码和题目不动，只把这一行留成过期、改成现在的路径，或整行删掉。Claude Haiku 5.5 和 Sonnet 5.5 都在 Claude Code 里跑，22 道题、一共 732 次。过期的测试命令，80 次里有 78 次走到已经不存在的目录；改对以后是 0 次。题目用不到的那个代码位置，84 次都没走。添加组件的步骤是 55/80。删掉测试命令后几乎不再走旧路径，但删掉步骤说明后仍有 20/80 次自己猜回旧目录。Sonnet 在测试命令上，过期时每题中位大约 7.8 次工具调用，改对后是 5.8 次，删掉后又回到 7.8 次。这个差别的区间不含 0，校正多项比较后不再显著，文中标成探索性结果。更清楚的是检查本身：80 次过期运行里有 64 次至少有一次命令其实没跑到测试，因为输出接进了 `tail` 或 `head`，壳层仍报成功。Sonnet 40 次里有 19 次，第一次检查修复时一个测试都没跑；改对的 40 次里是 0。三种条件下 bug 几乎都修好了。133 次走到旧路径的运行里，130 次后来找到现在的位置，中位再花两次调用；最终回复点明这条过期指令的只有 21 次。732 次里没有一次改过指令文件，也没有一次建议去改。

任务做成了，不代表过期指令没有代价。代理会绕开错误路径，却不改那一行。

### 2. When Routine Operations Break Architectural Pattern Relationships in LLM Agent Harnesses

人们把策略插件和审批插件都打开，就以为每次编辑都会先经过策略。真正决定检查顺序的，往往是回调的注册次序，或者一条已经保存的允许规则。重新应用插件、切换模式、保存同意，都不改插件代码，却会改掉这次运行里谁先看见这次编辑。

这篇是五个已发布 harness 上的案例比较，主样本是十四个独立编写的插件，不是随机大样本。在 DeepSeek Harness 上，策略回调和审批回调按注册顺序组成一条链，谁先给出答案，后面的就不再看。观察模式里，一次编辑能到达策略。按文档从观察切到强制执行时，策略插件被重新注册到审批插件后面。操作者随后批准了一次被禁止的编辑，它执行了，策略没有做决定。关掉再打开审批插件，评估又恢复。启用的插件和最终设置相同，操作历史不同，覆盖就不同。在 OpenCode 上，审查器只看还需要人工批准的请求。保存一条允许规则后，它不再审查，一次被禁止的编辑同样执行了。作者把“拦住坏结果”和“每条进入系统的编辑都要经过策略”分成两档。保住所需顺序、或把所需状态留住或重建的安排，在测过的路径和操作序列上守住了；另一些安排挡住了被禁止的效果，却看不到在别处就被拒绝的编辑。补充材料放在匿名地址，这次不附链接。

插件还开着，不代表策略还在检查。一次重载，或一条已保存的允许，就可能让编辑直接执行。

### 3. AutoRefine: Auto-Calibrating Code Judges from Workflow Outcomes

没有测试的代码改动，常靠一个语言模型裁判决定能不能送给人看。裁判的提示要按手头的任务校准，系统和代码一变，手工标签又会过时。合并或放弃、测试通过或失败，这些结果工作流里本来就有，但它们很吵：放弃可能是因为重复、流程，或裁判根本看不见的隐藏测试。

AutoRefine 用这些结果改写已经部署的裁判提示。改写之前，一个知情的教师看见裁判将要看见的内容，再加上结果。它能为保留的标签写出依据；结果无法从这份材料解释时，它弃权，把样本丢掉，而不是编一个标签。有执行结果、裁判还能看见参考补丁时，85 道留出的题、其中 13 道失败上，量规裁判与标签的偶然校正一致度从 0.36 升到 0.60。只调决策阈值时，失败召回 0.69、通过召回 0.80；校准后这两项是 0.64 和 0.95。拿掉参考补丁后，教师在验证集的 13 道失败里弃权 12 道，72 道通过里弃权 0 道，循环只到 0.35。工程师只看标题、摘要和补丁，也几乎认不出这些失败。把合并与放弃标签随机翻转约 25% 后，教师丢掉被改标的已合并样本的比例，高于丢掉真正放弃样本的比例（13/24 对 16/73，p=0.004），整体噪声从 24.9% 降到 20.4%。用它重标一个性能优化代理的裁判后，17 个从未参与训练或选择的当前差异上，一致度从 0.16 到 0.51，区间是 0.00 到 0.74，已合并样本的召回从 6/8 到 8/8。早先流程留下的 16 个差异上，旧裁判仍然更好，0.50 对 −0.02。样本小，循环每个设置只跑一次，教师和裁判同属一个模型家族。没有公开代码。

裁判要跟着当前流程重标。从裁判看见的内容解释不了的标签，应该丢掉。

**链接：** [原文](https://arxiv.org/abs/2611.09291)

### 4. ENGRAM: From Agent Experience to Weights through Verified Consolidation

代理可以把过去的做法存在外面，用到时再检索，也可以把它们训进权重。两件事常被当成一步：学会了，就把外部记录删掉。学生还不会某项技能时，教师示范不该被挡在训练门外。训练跑完，也不等于不检索还能做成。删早了，权重补不上，记录也没了。

ENGRAM 把“能不能拿来训练”和“能不能从检索里撤下”分成两次决定。技能按掌握程度，或按足够多的成功教师示范进入训练。学生用这些动作轨迹和一张经验图里的上下文，更新一个低秩适配器。撤下之前，留出的探针上比较两件事：更新后的模型不检索，对原来的模型加上检索。要同时过相对差距和一条绝对分数线，而且这项技能确实贡献了有效训练样本。没过的技能继续留在检索里。总表里的高低要小心看，文中写明是各方法自己的设置。更干净的是同一检查点上的撤下比较：HotpotQA 上保留全部 600 条时 F1 是 71.1；核对后撤下，可检索的剩 269 条，F1 是 70.9，配对差距 −0.2，95% 区间 −0.6 到 0.2，不能说没有损失。训练一结束就撤，只剩 13 条可检索，F1 降到 66.8。同样留下 269 条时，随机撤下是 67.6，核对后的撤下高 3.3。六个任务上，完整方法比只检索、不更新权重高 3.1 到 8.4 个百分点。ALFWorld 上它比只检索少用 42.8% 的输入 token，调用也少一些，但每题时间从 43.76 秒增到 65.91 秒。这是交互和问答任务，不是仓库级编码。代码在匿名地址，这次不附链接。

训练完成，还不等于可以删记忆。只有核对过、不检索也能做的技能，才该撤掉外部记录。

**链接：** [原文](https://arxiv.org/abs/2611.09472)

### 5. Control Room

代理采样一旦铺进强化学习和评测，停掉一个出了问题的任务，不能靠每份任务代码自己记得检查。任务代码经常改，也经常由不同的人运行。推理引擎的代码路径少得多，部署也更集中。

OpenAI 在研究基础设施里加了一层 Control Room。每个要做代理推理的研究任务先领一个任务编号，并挂到一份已批准的安全说明上。任务向引擎要 token 时带上这个编号。引擎在真正生成之前询问 Control Room：这个编号如果已经被标成停止，引擎就拒绝，不再交出模型输出。任务进程可以还活着，引擎也可以继续给其他获准的任务用。监控模型可以按编号要求停止；文中举的例子是此前一次与 DNS 有关的事件由监控抓住，这次不展开那次事件。从收到停止指令到不能再往下生成，最长 35 秒，这段时间来自授权缓存，他们正在把它压到 0。检查放在引擎里，是因为不能假设任务代码会正确询问自己是否还该跑。Control Room 自己不可用时，前沿研究任务上的推理请求会被拒绝，直到服务恢复。这一失败即关闭已经铺到前沿研究任务，其余研究任务写明还要几天。外部线上服务本来就更集中，不在这套系统的主要范围内。这些是厂商对已部署系统的说明，没有独立复测。

停任务的开关要放在推理引擎，而不是经常改动的任务代码里。服务自己不可用时，就应该拒绝出字。

**链接：** [原文](https://openai.com/index/control-room)

### 6. Knowing When to Intervene: Causal Evaluation of AI Agents

基准告诉你一条轨迹最后成不成。部署时要决定的是另一件事：这一次工具调用，现在拦下来查一查，最终结果会不会更好。只看已经发生的轨迹，拦与不拦并没有被分开。中途拦一次还会改变后面的状态和后面还有没有机会再拦，所以也不能把整条轨迹随机分成两组就回答“这一步值不值得”。

斯坦福的这篇在每个允许插手的时刻抛硬币，一半审查、一半直接执行，然后让代理继续。同一批轨迹可以估计：后面仍随机审查时，这一步审查的效果；后面不再审查时的效果；以及一条按历史决定何时审查的策略，相对于从不审查的增益。后两种要用结构模型，除了随机化本身，还要假设效果怎么随历史变化。零售客服任务里，被评的代理是 GPT-5 nano 和 Claude Haiku 5.5，审查者是推理力度为 high 的 GPT-6 Luna。nano 上，读和写的审查效果估计为正；取消订单和修改商品的区间在 0 以上，改付款的区间包含 0。Haiku 上，把所有读操作合在一起接近 0，单独看账户详情则区间在 0 以上。九条选择性策略各有 456 次直接重跑，结构模型则用另外 2,280 条逐步随机的轨迹。两种估计都为正，区间彼此重叠，直接重跑的点估计有八条落在结构模型的区间里。工具环境里的效果随能力和代理变化。另一组实验看的是对抗性反馈会在哪些状态下提高被禁止的测试修改，这次不展开那种反馈怎么写。没有公开代码。这些是较小模型上的估计，不是前沿编码代理的生产策略。

这一步该不该拦，不能从最终成败倒推。更长的策略比较，还要额外的模型假设。

**链接：** [原文](https://arxiv.org/abs/2611.09792)

### 7. Testing Claude on real-world electronics design

让代理改仓库里的代码，已经有一套工具。让它从一段话做出能送去制造的电路板，中间是几何、器件手册、工厂限制和固件，这些以前大多没有给模型用的稳定接口。一年前，Anthropic 和 Diode 试过的模型还不能稳定地摆放元件、把板子布完。

11 月 9 日的试验把 Claude Fable 5.2 放回这套工作里。三个设备各从一个短提示开始：USB 扬声器电话、语音助手底座、手持电子宠物。模型写规格和原理图，在板上放置元件并布铜，做外壳，写固件，列零件。Diode 按这些文件制造了三块板，没有再改电路。扬声器电话用了几周仍能工作，另外两台也还在正常使用。文中把布局能力的变化记在两个分数上：Diode 内部的 PCB Gym，把已有板子的布局拿掉再让模型重布，Fable 5.2 是 69%，Fable 5 是 25%；公开的 BenchCAD 2.1 上是 83.5%，将近前一代 Fable 5.1 的两倍。底座上从 100 脚连接器拉出的长线，模型判断 KiCad 自带的布线器需要太多逐步指令，于是自己写了一个网格搜索布线器，大约半小时，之后每条长线大约一秒。它先布高速线对，并让一对里的两条等长。制造检查标出六处过细的阻焊，它加宽开口、不移动零件；一处地与地的连接被自动检查当成错误，它判断这是有意的，没有改。外壳放不进直插的板子时，它算出大约倾斜 25 度可以装入，并写进装配说明。Anthropic 写明与 Diode 有商业关系。三台都还是原型：没有做电气验证、天线调谐、热测试和认证，也不是为量产设计的。模型没有连上测试仪器和制造设备，板子是人做出来的。

这三台的电路文件可以直接送去制造。电气验证、天线、散热和认证都还没做。

**链接：** [原文](https://www.anthropic.com/research/claude-electronics-design)

### Trending Open-source Projects

#### 1. Exact

代理要做完一个界面，通常得分别对付浏览器、桌面和手机，而且往往看不见自己做出来的东西能不能点。人可以来回切换窗口。代理需要同一份描述在每个平台上都能跑、能看、能测。

Exact 是 Expo 做的跨平台运行时，仍在 1.0 之前，写明没有稳定接口。界面用一种叫 Contract 的声明写，数据和逻辑用 TypeScript 或 Rust。编译结果是一份紧凑的计划：网页上变成一个大约 20 KB 运行时驱动的真实 DOM；macOS、iOS 和 Linux 上由 Rust 做布局，再用各自的原生界面或 GPU 绘制，界面路径里没有网页视图。仓库给代理准备了 `scripts/agent.mjs`。README 记录了一次干净克隆上的待办应用：缓存已经热过，代理大约 57 分钟做完，测试在网页、macOS 和 iOS 模拟器上通过，其中大约 25 分钟是第一次的 macOS 和 iOS 构建。这是项目自己的一次记录，不是一组重复评测。仓库建于 2026 年 11 月 2 日，本次读到 949 star、23 fork，MIT，最近一次推送是 11 月 9 日。没有逐日 star 差额。

它把“同一份界面，在多个原生宿主上由代理自己跑通”收成一个运行时。接口仍在每天变。

**链接：** [GitHub](https://github.com/expo/exact)

#### 2. vork

做三维和特效，常见工具是给人点的编辑器。代理更自然的做法是把场景、材质和着色器写成代码，渲染，看图，再改代码。编辑器里的一长串控件，对这种循环是阻力。

vork 是 Voyager 的无头三维与特效引擎，研究预览，源码在预览期可用。场景可以由代理写成代码，包括自己的着色器、材质、相机和物理，再在 GPU 上渲染。核心接口大约 2,500 token。引擎用 Rust 和 Slang，走 Vulkan 或 Metal。README 写，一百万只沿各自路径运动的鸟、192 帧 1080p，在一张 NVIDIA L4 上用了 97 秒；同样采样数下 Blender EEVEE 的时间是投影的 13 到 18 分钟，不是并排实测。默认静帧和短片上，它写自己比 EEVEE 快 1.1 到 2.3 倍。这些数字来自项目自己的测量说明。仓库建于 2026 年 11 月 5 日，本次读到 1,291 star、97 fork，许可证不是标准 SPDX 项，最近一次推送是 11 月 9 日。没有逐日 star 差额。

它让代理用一份短接口完成从场景代码到成片的循环。速度对照是项目自己的记录，鸟群相对 Blender 的时间是投影。

#### 3. CUI

给代理或人做一个小界面，常常要拉进一个浏览器，或者接一套很大的界面框架。依赖一多，构建和分发就变重。一份可以直接编译的 C 界面库，少掉的是这层运行时。

CUI 用 C99 提供原生组件，Windows、macOS、Linux 都能编，文档站把同一份库编译成 WebAssembly，用 WebGL2 画出来。组件是函数：自己画、自己处理输入，并把发生了什么返回来。README 写大约 190 个组件，一个完整应用大约 250 KB，没有额外依赖。仓库简介写的是大约 150 个，两处数字不一致，以仓库里的说明为准时要看你打开的是哪一处。本次没有重编示例。仓库建于 2026 年 11 月 5 日，本次读到 705 star、38 fork，MIT，最近一次推送是 11 月 10 日。没有逐日 star 差额。

它把一套可编译的原生界面收成没有浏览器运行时的 C 库。组件数量在简介和 README 里还不一致。
