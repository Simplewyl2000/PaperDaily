## 二、逐条中文讲解

### 1. Precedent or Intent? What Coding Agents Follow When Evolving Existing Code

仓库里的旧代码记下了过去的实现，很少记下当时为什么这样写。新任务到来时，几种写法都能满足功能要求。代理会跟着仓库里已经有的样子走，还是跟着任务说明里的新意图走，这两股力量以前混在同一次修改里，看不出来。

作者在专门建造的仓库里把三股指导拆开：模型自己的默认、仓库里的先例、任务里写明的指令。四个编码代理、六组成对的实现，一共 5,625 次试验，再到四个真实开源仓库、三种语言上复核。先例和模型默认冲突时，359/360 次跟着先例走。先例离得近不近，比例子有多少更要紧：旁边三个本地文件带来 96% 的采纳，同样数量的兄弟资源文件只有 4%；只改文件放在哪里，采纳可以从 0% 变成 100%。新意图和旧代码冲突时，写成优先级规则，比只放代码例子更有效。两个代理、两组实现上，联合成功是 59/60 对 38/60。在开源仓库里，由 harness 载入的一条规则把联合成功从 0/120 提到 117/120。论文没有给出代码仓库。

手边先例几乎总是盖过模型默认。新的优先级要写成规则，并由 harness 载入。

**链接：** [原文](https://arxiv.org/abs/2610.38244)

### 2. Context Is a Pipeline, Not a Window: Information Attrition in LLM Agent Harnesses

评测代理时，人们看两件事：上下文窗口有多大，最后答对了没有。窗口还很空的时候，工具返回的内容容易被当成已经进了模型。真正丢掉信息的地方，可能在到达模型之前的那几段处理。

这篇工作让代理阅读 Linux 内核跟踪，找出被注入故障的原因，并把上下文看成一条五段的管道。720 次运行里，最大的一次提示也只用了窗口的 5.75%。11,189 条工具结果里，有 3,827 条在进模型之前被截断，截完就不再是合法的 JSON。截断是按固定长度切文本，删掉的是靠后的字段。同一条结果里，一个字段只有 4.7% 的调用能到达模型，另一个字段是 99.3%。故障证据落在哪一个字段，取决于出问题的进程开始得早还是晚，诊断准确率和这个划分对齐。他们重放 864 条真实工具结果，其中一条生产跟踪在出厂切法下会删掉全部 128 条故障证据。对照实验里，这种切法首先表现为多干活：工具调用多 43%，计算量大约两倍，产出从 0.61 降到 0.31。只要还有别的路径，代理仍然找得到正确答案。七个代理框架里有两个用同样的切法。截断是不是准确率下降的原因，论文自己标成还没回答。论文没有给出代码仓库。

窗口几乎是空的，工具结果仍会在进模型前被切坏。多出来的代价先是重复劳动，准确率是否因此下降还没有被证成。

**链接：** [原文](https://arxiv.org/abs/2610.36114)

### 3. When Skills Tell Agents Not to Ask: A Large-Scale Study of Oversight Directives in Agent Skills

技能文件告诉代理遇到某类工作时怎么做。一份被广泛复制的技能里，如果有一行让代理不要请示、带上跳过检查的标志、或者继续做完再汇报，这一行会跟着副本进到每一个加载它的代理里。技能库的讨论多半在看它有没有用，很少逐句看它有没有把人的确认拿掉。

作者取 GitSkills 里 153 万份英文技能，把句子、条目、单元格和代码行拆开，手工标注 2,097 个单元，再训练检测器放大到全库。大约每 17 份技能里有一份含有放宽监督的指示，大约 8.8 万份。这些指示最常见的做法是权限标志，其中 70.1% 不限定场合。在监督用语同样多的技能里，会跑 shell、安装软件包或使用 sudo 的技能，出现这类指示的优势比是 1.7 到 1.8 倍，而且没有用更多收紧指示来补上。传播来自少数上游：带有这类指示的技能家族里，2.4% 占了副本的一半；1.1% 的不同指示单元占了出现次数的一半。开源扫描器最多抓到 46%，精确率低于 0.4。把同一份编码手册交给扫描器背后的语言模型，抓到 61%，精确率 0.71。论文没有给出代码仓库。

放宽监督的句子集中在少数被大量复制的上游技能里，而且多数不附带条件。

**链接：** [原文](https://arxiv.org/abs/2610.37734)

### 4. When Requirements Interact: Scaling Long-Horizon Coding via Interdependent Specifications

合成编程任务时，多写几条要求，很容易变成彼此无关的清单。仓库里真正难的是几条要求绑在同一份状态上：满足接口，可能碰坏错误处理；补上一种输入，可能让另一种用法失效。测试如果只接受某一种写法，又会把同样满足规格的解判错。

CodeSpecWeave 从真实开发留下的规格种子出发，让合成代理在仓库里同时改要求和可执行测试，故意把约束耦合在一起。审查代理再读多个模型的解题轨迹和补丁，丢掉放过残缺实现、或者拒绝合法替代的测试。试生成的 3,067 个候选里，2,267 个（73.9%）被自动审查标出对齐问题。留下的训练集是 2,865 个仓库上的 4,670 道题。两个总参数 310B、激活 15B 的混合专家模型在这上面做强化学习，并和 SWE-PI、MiMo Coding 比较。收益集中在长程的 DeepSWE-v1.1：MiMo-V2.5 从 12.39% 到 25.30%，Flash-SFT 从 54.42% 到 62.98%。SWE-bench Verified 和 Pro 上它并不总是最好的数据集。V2.5 在 Verified 上是 72.00%，低于 MiMo Coding 的 73.63%。他们自己的 100 题、1,044 条规格基准上，GPT-6 Astra 的通过率是 74.0%。论文没有给出代码仓库。

互相牵制的规格主要抬高长程任务的成功率。候选测试起初大约四分之三和规格对不齐。

**链接：** [原文](https://arxiv.org/abs/2610.40256)

### 5. Your Wish Is My Commit: Over-Compliant Refactoring in AI Coding Agents

重构如果没有“到这里可以停”的标准，代理每再改一次，都可能只是在响应用户的下一句“再改改”。代码已经干净之后继续改，写进仓库的是变动和审阅负担，不是更好的结构。

作者用 50 个算法程序和 10 个面向对象程序，让 Codex 和 Claude Code 配五种模型反复继续重构，一共三千多轮，并定义了六种过度遵从的行为信号。他们原本预期，一个够强的代理认出代码已经优化过就会停。五种模型都没有停。每个模型都继续改，第一次停下来之前，最多把代码写到原来的 31 倍；即便已经宣布任务完成，后面仍会再改。论文没有给出代码仓库。

开了头的重构没有自然的停止点。五个模型在代码已经干净之后都继续改，最多写到原来的三十一倍。

**链接：** [原文](https://arxiv.org/abs/2610.36346)

### 6. rTaste: Do Research Agents Have Taste? Evaluating Early Stage Research Judgment

自动化科研如果要自己决定先做哪个实验，就得在结果出来之前判断哪一个值得跑。能提出一串实验，和能把最值得做的排到前面，是两件事。排不好的话，先跑“它排第一的”并不会比先跑“它最先写下来的”更值。

六个前沿模型各自阅读七篇最近的自然语言处理论文，单独或组队提出最小可行实验，自己设一个通过阈值，预测能不能过，再排序。另一个执行者把包括排在最后的实验都做一遍，三个模型审计员评判结果。415 个实验里，194 个被判为可靠、有价值而且新；其中只有 73 个还被判为超出种子论文、并且不显然。代理的第一选择比随机抽取更常对上审计员最看重的那一个，但没有显示出好过“选它最先写下来的那个”。预测好过基线率，却没有明显好过一个只看到论文和实验登记的新实例。组队花费更高，提案质量没有明确提高。评测材料和全部 415 条记录是公开的。该仓库本次检索时 1 个 star，采用证据不足。

这些代理能提出值得做的实验，但排序还没有显出优于书写顺序。组队更贵，提案质量没有提高。

**链接：** [原文](https://arxiv.org/abs/2610.40488) · [代码](https://github.com/ArtKanke/rTaste)

### 7. kw-bench: Breaking Frontier Harnesses on Real-World Tasks

多数知识工作基准让代理根据一份简报去生成备忘录、表格或财务模型，再用量表或另一个模型打分。审计、税务和尽职调查里更贵的部分是查证：答案已经在不完整、彼此不一致的材料里，要还原出来，并且经得起核对。

kw-bench 的第一题族来自从业者描述的真实业务：把五年的增值税，从三代 SAP 的原始导出里还原出来。材料里有页眉、本地数字格式和不完整的链接表，没有说明这些东西如何相连。评分是确定性的，不用语言模型当裁判。四个套件在同一个模型 DeepSeek v4.1 Flash 上各跑两小时。两个不绑特定模型的套件给出了结果，OpenCode 0.542，micro-cc 0.528。两个离开原厂模型的实验室套件都是 0.00。作者把失败归到惯性：长会话里保不住许多很弱的线索。换到 Claude Opus 5.5 上，这道题几乎饱和，micro-cc 0.9986、Claude Code 1.000，分别用了 22 分钟和 25 分钟。论文没有给出代码仓库。

这道账上，小模型离开原厂套件就得到零分。换上前沿模型后，套件差别基本消失。

**链接：** [原文](https://arxiv.org/abs/2610.36405)

### Trending Open-source Projects

#### 1. deepseek-ai/dsh-superagent-prototype

仓库级编码代理通常要等一个人在会话里下指令。若它自己盯着 GitHub 和聊天，又可能把整个团队的注意力都占掉。

dsh-superagent 是 DeepSeek 团队放出的研究原型，说明里写明不是官方产品，也和内部文章里的设计不完全相同。它作为 DeepSeek Harness 的一个包，监听 GitHub，也可以监听飞书。允许名单上的人点名或私聊，才会形成明确请求；消息正文不能改写允许名单和授权范围。机器人最多产生一个推断候选，不能自己开一项明确任务。每个工单有自己的会话和目录。需要人处理时，面板把状态分成等待回答、等待复查或阻塞。仓库 10 月 31 日创建，本次检索时 2,781 star、245 fork。星数来自创建后不到一天的存量，没有单独的日增量统计。

它把“只在被点名或团队规则允许时动手”收成可检查的授权。执行会话以操作者的系统用户身份运行命令，且不再逐条审批，误授权的范围就是这台机器上的权限。

**链接：** [GitHub](https://github.com/deepseek-ai/dsh-superagent-prototype)

#### 2. unclebob/ub-mode

写给编码代理的技能，很容易停在“先做对、再做干净”这类句子上。圈复杂度、重复代码和测试杀不掉的变异，要有能算出分数的工具，句子才挡得住提交。

ub-mode 把这些步骤和三道确定性门放在同一份技能里。crapper 计算圈复杂度、覆盖率和 CRAP 分数，要求每个函数低于 10。dryer 标出相似度达到 0.8 的重复。mutator 做变异测试，留下没被测试杀掉的变异。技能仓库 10 月 25 日创建，本次检索时 5,835 star、319 fork，创建当天之后没有新的推送。三道门各自的仓库更早，星数少得多：crapper 175、dryer 76、mutator 96。

热度在技能包上，门本身还是小工具。它提供的是代理改完代码之后的硬门槛，仓库没有给出这些门能减少多少缺陷。

**链接：** [GitHub](https://github.com/unclebob/ub-mode)

#### 3. interplains/Zero-Breach-Toolkit

想知道自己的电脑或手机备份里有没有已知商业间谍软件的痕迹，若把检查交给会联网的服务，扫描本身又多一次外传。

Zero Breach Toolkit 在本机做只读检查，覆盖 Windows、macOS、Linux，以及接到电脑上的 Android 手机和 iPhone 备份。扫描过程不发起网络请求，也不修改被检查的系统。每份报告写明发现了什么、证据有多强、哪些地方没查到。作者写明，干净的结果不能当成已经安全。仓库 10 月 25 日创建，许可证 Apache-2.0，本次检索时 4,007 star、428 fork，11 月 1 日仍有推送。

它把证据强度和未检查范围写进默认报告。它查的是已知间谍软件留下的痕迹，不是未知植入的证明，也不是代理评测。

**链接：** [GitHub](https://github.com/interplains/Zero-Breach-Toolkit)
