## 二、逐条中文讲解

### 1. Benchmarks as Software: Terminal-Bench and the Case for Continuous Benchmarks

编码代理的基准在发布前会做人审、模型审计和找捷径。读者容易以为，这一轮审完，分数就能一直代表它想测的能力。Terminal-Bench 2.0 就是这样发布的。几个月后，任务跟踪里已经积了五十多条被标成任务缺陷的报告。模型会走出作者没写进测试的合法解法，依赖的软件包和网页也会在发布之后自己变掉。

他们把社区报告、任务文件、已有轨迹和参考解的重跑收成一条可重复的检修流程，人仍负责放行修改。89 道题里有 28 道被标出问题，大约三分之一；其中 14 道是这次新找出来的。便宜的审计模型对“任务在发布后漂了”这件事意见很散，所以漂移靠重跑参考解来抓，不靠模型投票。19 个代理在两版上重测，名次的 Spearman 相关是 0.958。拟合线大约是新分数等于 2.1 加上 1.04 倍旧分数，但抬升并不均匀：个别分数最多动 12 个百分点，名次最多动三名；原来低于 40% 的两个最弱代理，在修好的版本上反而更低。另一笔账是时限。失败试次里超过一半是超时，Claude Code 这一档到大约 68%。默认时限下，GPT 5.4 换脚手架大约差 20 个百分点；论文同时写，GPT 5.4 mini 的大约 30 个点差距会缩到 5 个点。把时限放到原来的 32 倍，GPT 5.4 换脚手架的差距大部分收回来。被判超时的试次里，仍有 11.8% 在交卷状态下是通过的。

分数最多动 12 个点，名次最多动三名。同一模型换脚手架的差距，把时限放宽之后大多收回来。

**链接：** [原文](https://arxiv.org/abs/2611.08417) · [代码](https://github.com/harbor-framework/terminal-bench-2-1)

### 2. Accepted but Wrong: Silent Failures of LLM Code Repairs after API Migrations

运行时或接口升级之后，有些坏掉是响的：函数没了，调用直接报错。另一些是静的：每次调用都成功，返回值却变了，比如枚举印成数字，或者求和的浮点更“准”了，却对不上账本。发布前如果只拿几条典型输入跑断言，这种修复会被放出去。

这篇预先登记了实验。73 道题覆盖 CPython 3.9 到 3.12、Node.js 20 到 24、SQLite 命令行 3.51 到 3.54 里的 60 处已记录变更。每个候选都在真实运行时上执行，隐藏的契约不给任何模型看。修复不是模型自由写出来的程序，而是在作者写好的片段里选择。在完整的修复空间上，只看典型输入、要求断言全部通过，会放行 0.410 的错误修复，误拒正确修复停在 0.010。从发布说明写出的一条边界输入，把放行比例降到 0.065；15 个当时还不存在的变更簇上，是从 0.471 降到 0.061。没看过程序、只看发布说明的 GPT-5.6-luna 写三条输入，描述性的结果是 0.070。预先登记的那道“只保留写作者声明仍然有效的输入”的门没有通过检验，放行比例停在 0.157。后面又冻了两阶段：菜单扩到 1491 个片段，再加入 233 个在典型输入上和旧输出一模一样的难例。难例在典型输入上几乎全部被放行，这是构造出来的。加上边界输入后，全部错误程序的放行比例是 0.058，但这批难例里仍有 0.168 通过；盲写的输入是 0.058 和 0.153。三个开源权重家族里，边界输入都减少了每次尝试放行的错误修复，正确完成没有下降。自测没有一项在多重比较之后还显著。没有公开的代码仓库，材料要向作者索取。

典型输入会放行四成错误修复。一条发布说明里的边界输入能降到约 6.5%，但看起来像对的程序仍有约六分之一漏出。

**链接：** [原文](https://arxiv.org/abs/2611.08269)

### 3. Multi-step SWE: Can Coding Agents Keep Building on Their Own Code Over Long Horizons?

开发者很少只丢给编码代理一个请求。他们会让它先做出一块，再在它自己写下的代码上扩展、升级、变快。多数基准一次只判一道题。就算把请求串成链，每一步如果只是一次短修改，也看不到“这一步本身就要做几个小时”时，代理会在什么地方停手。

Multi-step SWE 有 69 道题，每题 5 到 15 步，每一步是一份完整的工程请求，时限 2 到 4 小时，下一步从代理自己留下的工作区开始。九种语言，四类工作：把核函数变快、加功能、跟着版本升级、迁移技术栈。每一步的说明和检查尽量来自同一份已经存在的规格、发布记录或官方测试，而不是另写一套隐藏要求。九个前沿模型各做四次，整题只有每一步都满分才算做成。最强的 Claude Opus 5.5 整题解决率是 18.5%，四次里至少做成一次的题占 31.9%，单步通过率却有 56.8%。其余模型的整题解决率都不超过 17.8%。69 题里有 38 题没有任何模型做成，版本升级 20 题里占 16 题。失败很少是因为时间用完：只有 12% 的失败步骤跑到离时限不到五分钟；六个模型的失败步骤，用掉的时间中位数只有预算的 24% 到 37%。他们标注了 2,157 份收尾报告。52% 的失败步骤自称完成，而且没有指出任何没过的检查；另有 26% 已经说出失败的检查，却仍然停下，剩下的时间中位数是 66 分钟。代理说自己做完、又没有指出缺口时，验证器仍然判失败的比例是 57%，全部步骤的失败率是 65%。同一步、同一模型上，做成和做失败的会话时长中位数之比是 1.05。论文还没有做“从参考解接着做下一步”的对照，所以还分不开是这步本身难，还是前面留下的代码拖累了它。没有给出可打开的代码地址。

整题解决率最高只有 18.5%。失败多半不是时钟到了，而是代理在还剩一大段时间时，就宣布这一步已经做完。

**链接：** [原文](https://arxiv.org/abs/2611.07166)

### 4. Learning the Task or Learning the Verifier? Rethinking Criteria Exposure in Embodied Self-Improvement

让代理自己改技能库、越跑越好，通常会把基准的成功条件交给它看。这些条件原本是给模仿学习写的，常常比口头指令更细。指令只说按按钮，检查代码却要求蓝钮正好按两次，而且夹在两组红钮中间。模仿演示里这些细节本来就有。只拿到指令的代理没有。于是，分数上升，可能只是学会了这份检查代码。

他们把同一条自改进回路拆成两个开关。动手的是 GPT-6 Astra，把轨迹收成技能库的是 Claude Code 上的 Opus 5.5。打开开关时，学习器能读检查代码、分数和阶段；关掉时，它只知道这一局成没成。在 16 道“检查比指令更严”的题上，每道 320 个测试回合，读到原规则的库成功率是 51.6%，只看成败的是 27.8%。同一批回合改用只检查指令里那件事的规则再判，两边变成 45.0% 和 47.2%，优势没有了。检查和指令本来就一致的题上，只看成败也一样好。换到没见过的题，以及另外两个机器人基准，这两种库都不比空库有清楚的优势；只有在目标基准自己里面攒的经验才有用。项目页给出了说明，论文没有给出可打开的代码仓库。

读到原评分代码，成功率从 27.8% 升到 51.6%。换成只检查指令里那件事，这个优势没有了。

**链接：** [原文](https://arxiv.org/abs/2611.08318) · [项目](https://dagroup-pku.github.io/PyRUA-Lean/RSIJudge)

### 5. CORE: Coarse-to-Fine Search with Context Management for Deep Research

做深检索的代理要反复搜索，而 harness 决定每次交回多少字。搜得太碎，检索器对不上语义；把整段贴进上下文，后面每一步都要背着这些字。现在常见的做法是按文档或段落检索，再让代理自己，或者另叫一个模型，从大段文字里找出那两三句有用的话。

CORE 不改代理的权重。它先用稠密检索在最长大约 1024 个 token 的段落里找候选，再用一个后交互的重排模型给段落和其中的小段打分，把已经算出来的 token 相似度直接用来切出最相关的短片段，不再额外编码一遍。代理如果觉得片段不够，可以指定已经见过的文档，只在那篇里面把相邻两段拼回来；后一次搜索若交回同一片段，就换成一条短引用。干净的对照做在 Tongyi-DeepResearch-30B-A3B 和 BrowseComp-Plus 上：不许搜索是 4.58%；只按向量相似度交回段落是 62.61%；加上重排并只交短片段是 70.84%，高 8.23 个点；再加上展开和去重，到 80.12%，又高 9.28 个点。和另外两套开源 harness 比，三个模型、三套语料上都是 CORE 更高。语料从大约 10 万篇网页到 5.53 亿篇文档时，GPT-5.4 相对较强基线的优势从 3.49 个点拉到 12.28 个点，5.53 亿这篇上是 56.14% 到 68.42%。这组跨 harness 的比较里，基线没有用同一套重排模型，所以不能把全部差距算成“片段更短”。实验是封闭语料，不是开放网页。论文没有给出代码仓库。

同一模型上，把重排后的短片段交回去，准确率从 62.6% 到 70.8%；允许回到已见来源并去掉重复，再到 80.1%。

**链接：** [原文](https://arxiv.org/abs/2611.07859)

### 6. Scientist World: Grow a Research World for AI-Scientists

自动科研如果每次都靠人挑题目、人搭环境，环境的数量就长不过论文。文献对人来说是可做的问题，对代理来说往往只是可读的文本：方法复现不了，改进也没有统一的分数。

Scientist World 用一条没有人工审稿的流水线，把论文收成可执行环境：先复现原文方法并收回它的结果，再规定什么算改进、什么算抄近路，然后打包，并用另一组代理验收。他们从 14 个月里 124,816 篇论文筛到 1,000 个环境，偏向经验性的方法论文，也偏向算得动的。评分叫前沿归一化改进：0 分等于复现出的原文方法，正分表示在论文关心的指标上更好，可见集和留出集都会计入。真正拿来给前沿模型排名的，不是这 1,000 个，而是十个算力更低的环境。在这十个上，改进模式有 84% 的尝试胜过复现方法，从零设计有 74%。摘要里的“74% 的时间超过人类研究者”，指的是后一种，对照的是复现出的方法，不是把原文发表数字再测一遍。改进和从零设计的名次对不齐，论文因此把它们当成相关但不同的能力。训练时，小模型只负责出主意，所有主意都交给同一个 GPT 5.6 Sol 去实现。留出集上的中位分数从基座的 41，到监督微调后的 84，再到 GRPO 之后的 106；论文把 41 到 106 写成上升 158%。均值从 51 到 90。这证明的是“用这些轨迹可以让出的主意更好”，不是小模型已经能独立做完研究。项目地址写在论文上。

一千个环境可以自动建出来。超过原文这件事，目前只在十个低算力环境上、相对复现出的方法测过，而且出主意和写代码是分开的。

**链接：** [原文](https://arxiv.org/abs/2611.08478) · [项目](https://ai-scientist.world)

### Trending Open-source Projects

#### 1. Elephant-Goldfish Model

写规格的人和审规格的人如果坐在同一段对话里，审查者会顺着前面的理由往下走，没写明的假设就不容易被看见。编码代理把设计和审查放在同一个上下文里，也会这样。

Elephant-Goldfish 是谷歌放出的一套代理插件。Elephant 带着项目上下文起草规格。Goldfish 只看草稿和它引用的材料，不看前面那一段设计对话，用来把没说出口的假设露出来。人再决定取舍，批准之后才进入实现。仓库还带引导和漂移报告，软件规格是默认流程，别的文档可以换审查者和标准。插件 v0.1.0 于 2026 年 10 月 27 日发布，v0.1.1 于 11 月 6 日发布。本次用 GitHub API 读到 13,107 star、961 fork，Apache-2.0。仓库本身 9 月就建了，没有另算一周的增量。公开说明里没有对照实验，所以还不能说这种隔离提高了审查命中率。

它把“起草时带着上下文，审查时丢掉这段上下文”做成了可安装的流程。有没有因此少漏掉假设，还没有测量。

**链接：** [GitHub](https://github.com/google/elephant-goldfish-model)

#### 2. Poki

让代理操作手机，常见的路是模拟器、越狱，或者再买一块专门的硬件。真机上的应用、登录态和系统设置，这些路都接不全。

Poki 在 Mac 上跑一个本地 MCP 服务，让已经在用的 Claude Code 或 Codex 通过开发者通道操作一台配对过的 iPhone，不越狱，也不另加硬件。手机要打开开发者模式和界面自动化，先用 USB 信任这台电脑。它读无障碍信息、截图，并注入输入。启动应用时，必须看到前台进程号对上才报成功，观察最多三次，观察失败也不会再去点一次启动。无线安装和部分系统管理走的是另一条通道，文档写明它们不一定跟着输入通道一起可用。真机验证目前只覆盖中文界面、竖屏。仓库建于 2026 年 11 月 5 日，本次检索 423 star、87 fork，AGPL-3.0。日增量没有单独核对，硬件检查也没有在这次重跑。

它把真机操作收成现有编码代理可以调用的工具，并用前台进程来拒绝“说启动了但没看见”的成功。能稳定覆盖哪些系统和语言，公开记录还很窄。

**链接：** [GitHub](https://github.com/JosssphZhou/poki)

#### 3. ex-USSR Kinship Research

家谱代理如果只返回一个好听的家族故事，同名的人会被并成一个，同一份档案的复印件也会被数成两份独立证据。专业检索要的是另一件事：每个说法能不能指回原件，以及哪些还只是假设。

这是一份给 Codex、Claude Code 等技能运行时用的技能，覆盖前苏联十五个加盟共和国的教会簿、民事、军队、流放和镇压档案。它按事件发生时的行政区划找档案，而不是按今天的地图。主张只允许落在一组说得清的状态上，例如假设、单一来源、已印证、互相矛盾，不给一个百分比。同一份记录的副本放进同一个独立组，不能彼此充当印证。同名的人保持不同编号，直到门牌、父母、教父母、精确生日或部队把他们分开。一个本地脚本检查登记表的引用是否闭合，并标出还没有印证的说法；它查的是记录自洽，不是历史结论为真。仓库建于 2026 年 10 月 25 日，本次检索 2,071 star、206 fork，MIT，最近一次推送是 11 月 6 日。没有独立的准确率实验。

它把“证据能不能互相印证”写进了代理必须留下的登记表。脚本能挡住自己宣布自己已经印证，挡不住档案本身读错。

**链接：** [GitHub](https://github.com/DenisSergeevitch/ex-ussr-kinship-research)
